# 一期闭环可执行验收用例

日期：2026-11-22。关联 `phase1-core-acceptance.md`。本文件是验收执行表，不是通过证明。每个用例都须记录候选提交、配置版本、结果、证据和执行/复核人；自动夹具、真实联调、业务签收分别记录。

## 执行前置

- 使用隔离验收空间和受控测试数据。真实通知前明确试点收件人及窗口，不向生产用户批量发送测试消息。
- 准备两名普通员工 E1/E2、同组工程师 A1/A2、异组工程师 B1、组长 L1/L2、调度员 D1，以及两名不同平台管理员 M1/M2。测试标识仅为角色代号，不得用共享账号代替独立身份。
- 配置一条 INC、一条 GEN、一条批准的标准 REQ；确定默认支持组、岗位主备、任职有效期、优先级与服务日历。REQ 真实 OA 及交付条件未满足时保持入口关闭，并按关闭边界验收。
- 浏览器至少覆盖桌面和手机；每个越权用例直接验证服务端响应，不能只检查按钮隐藏。操作前后记录工单号、版本、状态、责任组/人、SLA 周期和事件编号。
- 多厂区用例须先完成 GAP-03；不能用不同支持组的现有测试替代厂区身份、目录、通知及报表隔离。

| U01 | BASE-01/P1-02 | M1 新建责任域、系统、岗位、人员任职及 INC 目录路由；提交后由 M2 批准 | 待审不生效；自审被拒；批准原子生效；员工可见目录，候选人来自当前有效任职；保留提案及发布版本 |
| U02 | P1-02 | 在待审期间修改同一配置，再批准旧提案；停用有在办单/目录依赖的组 | 旧提案版本冲突；依赖未处置不得停组；失败不移除成员、不撤销责任、不重置 SLA |
| U03 | P1-10 | 从独立门户使用已核实映射的企业身份登录；再使用未映射、被停用或错误企业身份登录 | 仅受信且在职映射成功；不按显示名/邮箱自动认领；无开发身份选单，无自动管理员授权 |
| U04 | P1-10 | 重放同一登录回调、两个浏览器互换回调、并发提交同一授权码 | 不串会话；同一尝试至多成功一次；错误签名/issuer/audience/nonce/过期均拒绝；日志无授权码或 Cookie |
| U05 | P1-10 | 停用 E1 或修改其身份映射，继续使用原会话；重新启用后重试 | 旧会话失效，重新启用不恢复旧会话；E2 不受影响；记录目录同步延迟与撤会话时间 |
| U06 | P1-10 | 两名真实管理员完成登录、独立授权和交接；执行管理员不足的恢复演练 | 日常不自批；普通撤权遵循管理员连续性；账号停用仍可执行；历史存在时不可重跑首次初始化冒充恢复 |
| U07 | P1-01/P1-04 | E1 填写普通 INC 并重复点击提交；E2 尝试读取/操作该单 | 相同幂等请求只有一单；不同请求体复用键被拒；E2 不因知道工单 ID 获得读取或操作权 |
| U08 | P1-01 | 提交敏感描述、敏感附件或被策略拒绝的语音/字段；再绕过页面直调接口 | 在普通持久化与模型调用前拒绝/分流；工单、附件、草稿及 outbox 无拒绝内容；记录拒绝事件但不复制敏感原文 |
| U09 | P1-04 | 提交 GEN，由 D1 纠正服务分类；普通工程师及撤权 D1 再尝试同一操作 | 仅当前有权限者可纠偏；保存原始目录/字段和新路由快照、原因、责任历史；不能借分类跳过 REQ 审批 |
| U10 | GAP-03 | E1 属甲厂，E2 属乙厂；同名服务按厂区配置岗位；尝试伪造客户端厂区及跨厂查询/改派 | 厂区来自可信映射；正确路由和隔离；未知厂区不默认跨厂；通知、报表、旧单和交接均遵循同一边界。当前未实现，不得填写通过 |

| U18 | P1-03 | 触发 P1 候选；由不同的授权复核人确认，制造未确认及降级情况 | 即时告警、超时提醒及确认有独立记录；未确认不静默降级；等级变更保留既有 SLA 义务，不能靠降级清零超时 |

## 处理、申请交付与收尾

| 用例 | 对应项 | 操作 | 预期结果与关键证据 |
| --- | --- | --- | --- |
| U22 | P1-04 | A1 请求用户补充，E1 回填；再进入供应商等待、到期提醒及恢复 | 等待原因/责任人/期限齐全；用户等待与厂商等待按各自 SLA 规则计算；提醒可恢复且不重复；恢复不丢原责任 |
| U23 | P1-04/P1-08 | A1 提交解决方案，E1 确认、重开；另一工单测试待确认自动关闭 | 申请人才可确认/重开；解决分类及回执完整；自动关闭基于解决时间，交接或后台更新不延迟关闭；重开保留上一周期 |
| U24 | P1-05 | E1 从已批准 REQ 版本申请，提交漏字段、旧版本、超期或不可见服务 | 合法请求完整入库；其余拒绝；未配置真实审批时入口保持关闭；INC/GEN 不得变相绕过 REQ 交付权限 |
| U25 | P1-06 | OA 正常同意/拒绝/撤销，重复及乱序回调；构造签名错误、未知实例和审批结果不明 | 仅正确关联及有效回调能推进；至少覆盖超时、对账及失败恢复；未批准不能创建交付成功；保存实例和审批证据 |
| U26 | P1-07 | 合格工程师提交交付意图并提供回执，另一合格人员复核；重放和并发执行 | 状态区分待执行/处理中/失败/复核/完成；本人不能自审；同一命令恰执行一次；失败不能写成功或让请求直接关闭 |
| U27 | P1-07 | 在执行前撤销岗位/人员资格；构造外部结果未知、重试及恢复 | 执行时复查资格；结果未知进入调查/对账；恢复不重复交付；平台管理员身份不能替代业务审批或交付资格 |
| U28 | P1-07/P1-08 | 授权到期或请求撤销，形成回收待办、实际回收和独立确认；员工查看进度 | 提醒到当前有资格的人；回收有回执，业务申请人可见其必要进度；内部审批/调查敏感信息不越权展示 |
| U29 | P1-08/P1-12 | E1 评价服务/知识，E2 冒用评价；工程师提交知识，由独立人员发布、撤回 | 评价有主体、幂等及防篡改；发布和受众受限，旧版本保留；内部知识和处理记录不因通知链接变成公开 |

## 验收记录与放行

每例记录：`用例编号 / SHA / 环境与配置版本 / 执行时间 / 操作者和复核人 / 数据引用 / 预期与实际 / 自动证据 / 真实联调证据 / 缺陷编号 / 签收结论`。日志须脱敏，凭据不进入代码仓库或本表。

状态分别为“未执行、未通过、自动验证通过、真实联调通过、业务签收”。S1 放行须覆盖实际启用范围的全部用例，安全越权、丢单、未审批交付和失败标成功不得带缺陷开放。GAP-03/07/08 仍属代码差异；相关范围未完成前不得宣称蓝图全量实现。未启用模块应在试点说明中明确，不计算成通过。
