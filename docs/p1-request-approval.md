# P1-06 OA 审批编排候选

日期：2026-11-10。阶段：一期 REQ/OA。本文描述代码候选及待验收边界，不代表真实钉钉 OA 已联通。

## 本轮实现

- `007_request_approval.sql` 新增主管映射、审批账本、不可变快照及追加式事件、已验证回调提示去重表。既有迁移不改写，迁移就绪检查和失败回滚探针随新编号更新。
- `enqueueRequestApproval` 供将来的 REQ 建单事务内部调用；要求申请已获授权并通过普通内容保护，工单处于 `WAITING_APPROVAL`，已发布目录版本与工单快照完全一致，有效期不超过目录策略。审批意图与建单应在同一事务提交/回滚，重复意图不重复建账。
- 审批人从不可变目录版本解析；主管从显式、未过复核期限且有在职核验人的映射解析。申请人、主管和各级审批人均须有同企业的稳定钉钉身份；禁止自批及重复审批人。不从昵称、手机号或支持组成员资格推断主管。
- 快照固定目录版本、模板、实际申请标题/说明/字段、申请人/审批人身份、主管映射依据和请求有效天数；后续申请范围或请求对象改变、身份失效/替换或主管映射变化均阻止继续审批。目录新版不改写历史快照；真实 OA 适配器应只使用此不可变申请快照构造表单。
- 以短事务申领租约，外部调用不持有数据库事务。创建调用先落账，最多调用一次；创建超时、异常或 worker 中断一律按“创建结果不明”处理。仅在真实适配器具备可核验能力时找回既有实例；不存在/查不到实例不构成再次创建的授权。多次仍不明则转受阻待人工对账。
- 已验证回调只按企业/事件 ID 去重并唤醒查询，不接收“回调声称已批准”作为状态变更输入。以适配器的权威查询核验企业、实例、模板、申请人及有序审批链，再更新审批状态；不假设钉钉原始响应天然具备这些字段或可按外部引用查找。
- 新的已验证回调立即清除批准凭据，将已有 `APPROVED` 暂退为待复查 `PENDING`，并使正在进行的旧查询租约失效；旧查询迟到不能覆盖新回调。重复事件不重复修改状态；拒绝/撤销等终态不复活。历史权威批准记录仍用于拒绝上游退回待审批的异常状态，不因清除当前凭据而丢失。
- 拒绝、撤销、超时、工单取消、人员失效、身份变化及绑定不符均不得进入交付。查询失败会清除本轮批准证据；已批准结果继续对账，撤销不会被迟到回调复活。审批通过不改变工单为“已交付”，本轮不创建交付任务。
- worker 接入周期性超时和本地资格检查；真实创建/查询适配器尚未配置，因此生产路径不自动发起 OA。审计只保存状态和固定原因码，不保存回调原文或上游错误正文/密钥。

## 适配器与开放门槛

目前没有新建公开回调路由、模拟 HTTP 接口或自动开通配置。`POST /tickets` 对 REQ 的服务端阻断保持有效；真实 OA 接入及 P1-07 交付未验收前，不开放申请。

现场须确认模板及表单映射、模板版本治理、应用权限、审批人顺序/代理规则、主管映射权威来源和核验责任、审批超时策略、签名/解密/时效与事件 ID 规则。根据现场版本与官方文档实现真实适配器及经过鉴权的回调入口，不将接口抽象视为钉钉能力证明。

创建结果不明且无法自动找回时，由 OA 管理员按批准的操作规程核查是否已有实例，记录依据后处理；不能删除账本、清零创建次数或直接重置为排队状态。工单取消/人员失效时保留已知 OA 实例供追踪；外部实例撤销与通知仍待真实接口实现，本轮不宣称已自动撤销 OA。

P1-07 必须在交付事务中重新核验审批最终有效性、工单状态、人员身份、适用范围与期限。账本 `APPROVED` 只是一次查询观察，不是永久授权令牌。交付、复核和回收任务独立留证；不得用本轮测试替代此闭环。
