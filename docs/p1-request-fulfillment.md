# P1-07 受控人工交付核心（代码候选）

当前仅实现内部函数和不可变迁移，未提供交付 API、员工入口或下游系统自动开通。REQ 服务端阻断继续有效；真实 OA 接口和业务策略未联调前，不将本能力记为上线或验收。

## 规则

- 审批账本为 `APPROVED` 且有当前验证凭据仍不等于授权。准备任务和确认人工交付前，都重新向 OA 读取权威实例，并在同一数据库事务中核对实例、企业、模板、申请人、审批人、不可变申请内容、在职身份、主管映射、工单状态和期限。回调先到会清除凭据，阻断旧查询结果。
- 交付人员必须在责任组任职且在职，不得是申请人或审批人。交付任务按审批和工单各限一条，留存受理人及 `READY` 状态。实际执行后，凭外部变更单编号记录交付时间、不可变有效期和执行人；数据库不保存密钥或下游凭据。重复交付被拒绝。
- 交付后由另一名在职责任组成员复核下游实际授权并留存独立外部记录编号；复核人不能是执行人、申请人或审批人。复核只补充不可变时间/身份及事件，不改变交付状态，不能代替真实下游核查。未复核的交付仍需追踪，复核超时升级与工作台入口尚未实现。
- 取消、撤销、拒绝、人员失效、身份变更、审批失去验证或到期时，未执行任务转 `BLOCKED`；已交付任务转 `REVOKE_DUE`，等待人员在下游撤权并凭外部变更单编号登记 `REVOKED`。此处仅产生回收义务，不谎称已经自动撤权。
- OA `expires_at` 是首次交付截止时间；已审批且已交付的访问期限由 `access_expires_at` 单独控制。回调让批准凭据失效时，现有交付需要进入待回收。已交付后不自动改变工单状态，以免现有 `WAITING_APPROVAL` 约束误判；业务状态集成需在开放入口前一并设计验收。

## 开放前缺口

真实钉钉 OA 创建、可信回调与权威表单读取，业务审批矩阵确认；操作员权限 API/幂等性、受理与复核入口、通知及超时升级；人工执行失败的补偿记录、下游撤权回执与抽样核查；工单状态和员工进度；在 `10.10.81.125` 的隔离部署、恢复演练与业务验收。未经这些条件，不开放 REQ 提交、交付动作或权限自动化。
