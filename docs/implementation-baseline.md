## 开发门槛

- 执行顺序优先于主规格旧 T01 至 T11 的编号排列。原 T10 中的 GLPI 只读关联归 P2-02，A08 的真实资产集成验收在二期；首期仅验证入口关闭、拒绝伪造资产引用且不影响文字报障，不以 GLPI 接口未就绪阻塞一期。
- 当前业务切片为 BASE-01 核对后补齐 P1-01 至 P1-04。P1 候选立即通知并启动响应，不等待主管确认；确认、调整、通知失败及升级均须留痕。骨架或 CI 通过不代表该业务切片完成。
- 每个切片记录 ID、依赖、确认人、代码/API/迁移、权限、审计、失败路径、测试、真实联调、部署版本及验收结论。公共身份/审计/通知依赖随当前切片补齐。
- 敏感证据不能因为 SEC 延期而进入普通工单、草稿、日志、通知或外部 AI。无受控接收能力时，相关敏感入口保持关闭，引导至现有安全渠道；不宣称关键词检测能完全识别安全事件。
- 一期人工权限交付/回收任务不等于三期自动执行；审批通过不等于交付成功。
- 二期监控只先接可用性/性能告警，CI 不重复建主数据；恢复不自动关单，接入故障保留原平台通知。
- Mac 只编辑和 Git；运行与测试在 GitHub CI 或 10.10.81.125。业务参数、真实接口授权和未实现功能不能用假适配器绿灯替代验收。
- 后续需求保留 ID 与目标阶段；不静默删除，不把预留字段记为交付。所有当前能力仍需逐项验证，本文不自动将任何需求标为已验收。
