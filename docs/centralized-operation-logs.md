# 集中操作日志设计与验收

日期：2026-11-24。适用范围：本次代码变更；合并和部署状态以发布记录为准。

## 页面职责

- 管理员从左侧“操作日志”统一查询已记录的系统操作与配置变更。
- 配置页面显示当前生效配置、维护表单及仍需处理的审批；不再混排已完成历史。保留“查看相关日志”，自动携带模块和可用的对象筛选。
- 工单详情保留提交、分派、接单、处理、解决、用户确认、关闭等业务时间线。集中操作日志可查询已有工单审计，但不替代业务时间线。
- 通讯录同步状态和消息投递状态仍留在相应运行页面，供故障处理使用。

## 查询与详情

筛选支持关键词、操作人姓名或 ID、模块、结果、精确操作对象 ID、开始和结束时间。时间输入按浏览器本地时区转换为带时区时间。默认每页 20 条，按时间和唯一日志 ID 倒序排列。

详情显示执行者、时间、模块、对象、动作、结果、依据、源记录、已记录的请求 ID 及修改前后差异。提交或拒绝的配置使用“拟修改为”标示，不代表配置已经生效。管理员直接配置显示“保存并生效”。底层分别记录的提交与生效事件均保留，同一事件在通用审计中的镜像记录去重。

差异最多展示 200 项，超过时明确提示截断。快照数组最多展示 3000 项。缺失的历史快照、请求 ID 或执行者显示“历史未记录”，不推测、不补造。对象显示名称可能来自当前主表；对象 ID 和原始审计来源用于定位历史记录。

服务目录与组织配置一起发布时，详情同时展示目录字段、发布状态及组织映射变化。目录快照取自对应发布版本；修改前取上一目录版本或当次保存的原始快照，后续维护不会重写历史详情。

## 数据与权限

迁移 `050_operation_logs.sql` 新增只读视图 `operation_log_entries`，聚合现有审计来源，不搬迁或删除历史记录。来源包括服务组织、岗位任职、支持组、角色权限、派单、主备规则、目录分类、服务发布、分级、日历、厂区配置、工单、知识、附件、人员同步及通用操作审计。

接口：

- `GET /api/v1/admin/operation-logs`
- `GET /api/v1/admin/operation-logs/:id`

后端每次查询重新检查真实有效的平台管理员资格。普通员工、仅有组内职责的工程师、停用员工及过期管理员均不可查询。查询参数严格校验并参数化，关键词中的 SQL 和通配符按普通文本处理。接口不提供日志修改或删除。

配置快照采用字段白名单；工单审计仅展示流程和责任字段，不展示报障正文、自由表单内容或附件存储地址。文本中已识别的令牌及凭据格式会隐藏。不得将密码、密钥等敏感内容写入变更依据。

本次聚合的是系统已实际写入的审计，不承诺所有 HTTP 访问、查询动作、失败尝试或外部系统操作都已有历史记录，也不提供数据库超级管理员不可篡改保证。未来新增写操作应在业务事务中写入对应审计，包含执行者、对象、动作、结果、时间、请求关联及安全的前后快照，并纳入此统一投影。无历史快照的来源继续按事实展示。

## 发布验收

1. 对合并提交执行 CI，按既有发布流程核验制品并备份数据库。
2. 正常执行数据库迁移，再启动对应 API、前端和 worker；确认运行版本一致。
3. 以真实平台管理员登录，检查“操作日志”入口及旧记录查询。
4. 做一次可恢复的配置修改，从“查看相关日志”确认提交与生效记录、执行者和差异正确；恢复配置并确认恢复记录。
5. 以普通员工确认无全局日志访问权，抽查现有工单业务时间线完整。
6. 如需回滚应用，保留只读视图和原始历史，不删除或修改已执行迁移的校验记录；按发布手册处理数据库兼容性。
