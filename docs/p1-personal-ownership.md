## 数据与权限

- 一个 `owner_group_id`，一个可空 `assignee_id`；未认领时由责任组负责。
- 新增迁移 `003_ticket_ownership.sql`，不修改历史迁移。旧工单保留原状态、组和 SLA，个人责任初始为空，组内有效成员须认领。
- `ACCEPT` 绑定当前操作人；工单行锁、版本号和幂等键防止并发双负责人。同组成员可读，不能替当前处理人请求补充、等待厂商、解决或交接。
- `REASSIGN` 现在是发起交接，必填目标组、指定在职成员和原因；可同组换人。原组、原处理人在接收前继续负责，不即时转派。
- 目标人员可读这一张待交接工单，不因待交接而向整个目标组开放。仅指定人员可 `ACCEPT_HANDOVER` 或 `DECLINE_HANDOVER`；需回复或退回原因。原处理人可 `CANCEL_HANDOVER`，需原因。
- 对组内尚未接单的 `QUEUED` 工单，可指定目标接收人；确认前仍归原组。其他进行中工单须先认领，才能交接。
- 交接确认保留原业务状态；仅 `QUEUED` 变为 `IN_PROGRESS`。已结束工单不接单、不交接；关闭或撤销清除待交接引用。
- 动作写入同一事务中的事件、责任前后值审计和 outbox。成员及人员状态在写事务中重新检查，不只依赖页面隐藏按钮。
- 幂等重放仍须具有当前访问权限；责任已移交而失去权限的原处理人不会通过重放获得工单内容。

## 人员失效与通知

- worker 周期检查当前处理人停用或退出责任组：清除个人分配及待交接，退回原组待认领；保留业务状态和 SLA 周期、起算点、暂停及完成记录，新增恢复事件和审计。
- 仅待接收人失效时撤销待交接，原处理人继续负责。恢复检查批量 100 条，采用工单行锁和跳过已锁定行；约 30 秒一轮，不承诺外部人事事件实时生效。
- 每次 API 身份验证检查在职状态；worker 删除已停用人员会话。正式钉钉/AD/HR 停用来源及同步时效仍须联调，不宣称已经完成离职系统自动集成。
- 待接收人加入消息收件范围；发送前重新核对在职、组成员或指定接收权限，避免已失权人员继续收通知。开发模拟不算真实送达、不计首响；真实接单或接收回复送达申请人才可计首响。
- 无有效组员、交接长期不确认和主管强制接管仍需要后续主管角色、值班及升级策略；不能给所有工程师隐式主管权限。P1-02 不能据此标记整体验收。
