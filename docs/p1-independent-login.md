# 独立门户企业账号登录

S1 要求 ITSM 可独立提交、处理工单。本批增加可选 OIDC 授权码登录，复用现有员工、会话、CSRF 与工单权限。协议使用 `openid-client`，默认关闭；没有企业身份提供方和受信映射时不能宣称正式独立登录已完成。

## 接入准备

1. 企业提供支持 OIDC discovery、授权码及 PKCE S256 的 HTTPS 身份提供方；在 IdP 注册机密客户端，回调固定为批准的 ITSM HTTPS 根地址加 `/api/v1/auth/oidc/callback`。
2. 在服务器私有配置中设置 `ENABLE_OIDC_LOGIN=true`、`COOKIE_SECURE=true`、`ITSM_PUBLIC_URL`、精确 `OIDC_ISSUER`、`OIDC_CLIENT_ID`、`OIDC_CLIENT_SECRET`。正式环境关闭开发身份，浏览器须信任证书。issuer 的尾斜杠也是精确身份的一部分。
3. 先从批准的目录源建立真实员工；由企业身份管理员核实 IdP 的不可变 `iss + sub` 与现有 `employee_id`，记录审批编号。管理员通过受控数据库变更写入 `oidc_identity_links` 的四项：`issuer, subject, employee_id, approval_ref`。禁止靠邮箱、显示名或客户端自报字段自动认领；禁止写入访问令牌。该表当前没有自助关联 UI，操作须纳入现有数据库变更和双人核对。
4. 身份关联不授予岗位、支持组或平台角色。角色仍经现有提案及独立复核；至少两名真实管理员完成交接。无有效管理员时遵循管理员手册的带外恢复流程。
5. 所有外层代理、WAF、负载均衡和追踪系统不得记录回调查询串、授权码、Cookie 或凭据。仓库内 Nginx 已关闭此回调的访问日志；外层配置仍须现场核对。

## 会话与运行

登录使用随机 state、nonce、PKCE、浏览器绑定的 Secure/HttpOnly/Lax 临时 Cookie，5 分钟内一次有效。服务端原子消费尝试后再换码，验证签名、issuer、audience、有效期和 nonce，只允许已映射的在职员工。最终复用 8 小时 ITSM 会话，业务写入仍需 CSRF。

映射修改或删除会撤销旧员工的 ITSM 会话；停用员工复用现有即时撤销机制，重新启用不恢复旧会话。门户退出仅清除 ITSM 会话，当前不提供 IdP 全局退出或 IdP back-channel logout。IdP 禁用未及时同步至 ITSM 时，已有会话可持续到本地过期，因此应配置可信目录停用同步和紧急会话撤销流程。

临时尝试仅保存 state/browser 哈希、PKCE verifier 和 nonce，不保存授权码、IdP token 或原始 Cookie。过期记录在下次登录开始时清理；如需固定保留期清理，由运维在受控数据库作业中删除 `expires_at <= now()` 的记录，并核对数据库备份保留期。入口需在外层部署访问频率限制；多用户经同一代理时须使用可信客户端地址，不能直接信任外部伪造的转发头。

## 验收门槛

| 项目 | 自动验证 | 真实验收 |
| --- | --- | --- |
| 协议校验 | 正确签名，错误签名/iss/aud/nonce/state/过期拒绝 | 企业 IdP 正常与失败登录 |
| 身份边界 | 未映射拒绝、同一回调并发只成功一次 | 两名同名员工不能串人，非试点人员拒绝 |
| 撤销 | 映射变更、停用后旧会话失效 | 目录停用同步及岗位撤销 |
| 界面 | 固定登录链接，无开发身份选择，手机无横溢 | 独立浏览器建单及工程师处理完整闭环 |
| 运维 | 配置默认关闭、固定回调及 Cookie 属性 | 真实 HTTPS、代理日志脱敏、凭据轮换、管理员交接 |

已有 `verify-enterprise-uat` 检查主要面向钉钉就绪，不能代替本表 OIDC 验收。该检查通过不代表 IdP 已接通。
