# 工程师责任队列（第一期）

## 查询契约

`GET /api/v1/tickets?mine=false&queue=all|assigned|incoming|outgoing|unassigned&status=...&page=1&size=20`。
省略 `queue` 等同 `all`，仅工作台可传队列；`mine=true` 传队列或队列值无效返回 400。
继续沿用原有工单可见性边界：责任组成员、P1 复核人员及被指定的待接收人。
队列只收窄范围，绝不单独授予工单读取权限。列表项含责任组、当前处理人、待接收人姓名；API 始终只映射明确列出的公开字段。

- 全部可见：原工作台可见的全部工单，含历史终态。
- 我负责：未结束且当前处理人是本人，同时本人仍为责任组成员。
- 待我接收：未结束且待接收人是本人，同时本人仍为目标组成员。
- 待对方接收：未结束且本人仍在责任组、仍是当前处理人，且有待接收人；与“我负责”有意重叠。
- 组内未接单：未结束、当前处理人和待接收人均为空，且本人仍在责任组。包括责任恢复后尚未重新接单的处理中工单；已指定接收人但尚未确认的工单不计入。

终态为 `CLOSED`、`CANCELLED`、`REJECTED`。`workQueues` 返回五类计数（不受状态过滤影响）；`counts` 是当前队列的状态汇总（同样不受状态过滤影响）；`total` 是当前队列与状态过滤后的数量。页数据、状态汇总、队列计数来自同一 SQL 语句的可见数据快照。无权限者不会因为参数得到额外内容。

## 实施与验收

沿用原有 API 会话、在职检查、组成员和交接动作权限。刷新时队列计数随当前身份变化；开发身份切换清空旧列表。工作台显示责任信息，移动端两列队列入口。
CI 的所有权集成用例覆盖并发认领、交接、回退、禁用与成员退出后的队列可见性、状态统计和无权限拒绝；Playwright 覆盖桌面与手机的队列切换、交接及接收。Mac 不运行应用依赖、测试与容器。

本切片不包含值班排班、自动分派、超时升级或钉钉卡片直接处理；不能因此宣称工程师全链路已经完成。它不涉及数据库迁移；合并后仍需按既有受控发布入口和合成业务验收在 `10.10.81.125` 核验。
