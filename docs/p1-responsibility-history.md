更新日期：2026-11-18。范围：P1-02、P1-13、R5 和 V1.2 第 16.7 节。

状态：代码候选，尚未通过包含本修改的完整 CI，未合并、未部署，未完成桌面/手机截图复核或业务验收。当前责任报表与历史责任报表分别保留，不用任一报表代替另一报表。REQ 正式入口仍关闭。

## 1. 记录模型

迁移 `031_responsibility_history.sql` 新建 `responsibility_recording` 和 `ticket_responsibility_history`。在同一迁移事务内锁住工单表的并发写入、建立记录起点、为全部存量工单写入 BASELINE，然后安装工单 INSERT/UPDATE 触发器，不留初始化与启用之间的漏记窗口。迁移由既有工具统一管理事务，不单独提交。

每条记录包含工单 ID/编号、逐单 revision、来源 CREATED/BASELINE/CHANGE、数据库观察时间、时钟修正标记、工单版本、责任 epoch、实际责任组/人员及其姓名快照、状态、服务类型/代码、待接收安排及精选路由标识。记录中没有标题、正文、评论、凭据、OA 表单或通知内容。路由版本保存为可空文本，不对旧 JSON 元数据额外施加整数转换限制。

- 新工单从 CREATED 开始。存量工单只从迁移时间的 BASELINE 开始，不能用建单时间回填未知责任，也不从现任负责人推算历史。
- 实际责任组、负责人、状态、服务、编号、待接收安排或路由快照变化时追加；仅改正文、创建日期或版本不追加。
- 每个工单的行锁串行化更新。历史记录与业务写入同事务提交/回滚，revision 连续递增；API 和 worker 的正常工单更新均会经过触发器。
- 姓名及组名取自该次工单观察时的人员/组档案。单独改名不切割工单区间；下一次相关工单变更才产生新名称快照。同一人员 ID 可保留多个历史名称，停用不删除记录。
- 观察时间来自 `clock_timestamp()`，发生回拨时夹到上一观察时间并标记。相同时间的记录保留 revision，零时长区间不进入时长报表。标记不是自动校准时钟或修复历史的证明。
- 时间是数据库执行写入时的观察，不是事务提交时间、人的实际动作时间、消息送达时间或劳动时间。一个已提交事务中的多个相关更新可能形成多条观察；回滚事务不留下记录。

## 2. API 和统计口径

`GET /api/v1/reports/responsibility-history`

参数与当前报表统一：必填 `groupId/from/to`；`serviceType` 为 INC/REQ，默认 INC；`ownerScope` 为 ALL/UNASSIGNED/PERSON，PERSON 必填 `employeeId`，其余模式禁止携带人员 ID。拒绝重复、矛盾参数及无效日期；开始与结束日期最多相隔 30 天，即最多覆盖 31 个自然日期。

响应明确声明：`attribution=HISTORICAL_OWNER_GROUP`、`windowBasis=INTERVAL_OVERLAP`、`durationBasis=WALL_CLOCK_SECONDS`、`timeZone=Asia/Shanghai`，并提供 `asOf/recordingStartedAt/windowStartsBeforeRecording`。

1. 在 REPEATABLE READ、READ ONLY 事务内重查当前在职状态和支持组成员资格，未授权返回 404；身份已失效则由认证拒绝。权限以该事务快照为准，不声称请求执行中跨事务即时撤权。
2. 使用相邻 revision 的观察时间建立半开区间；必须先找到下一记录，再按历史责任组筛选，避免跨组后的时间错误延长为旧组责任。
3. 只取与所选上海日期区间有正时长重叠的记录，并裁切到查询起止和 `asOf`。不按工单创建日期取样；未来查询截止日期不能把当前区间延长到未来。
4. 返回完整授权组范围的历史人员分布，总指标和明细再按人员过滤。个人筛选不扩大权限，也不能用来绕过完整组范围的查询限制。
5. 完整范围超过 5000 个正时长区间，返回 503 `REPORT_HISTORY_WINDOW_TOO_LARGE`，不返回带有伪总数的截断结果。

指标包括不同工单数、区间数、未结束归属秒数、未接单秒数、待接收秒数、等待用户/外部/审批及待确认秒数、涉及存量基线的工单数和时钟修正区间数。等待和待接收指标可重叠，不应相加当作净工时；跨人的工单数也不可直接相加去重。

CLOSED/CANCELLED/REJECTED 区间仍可追溯，但不计入未结束归属时长。重开追加新区间，不删除终态区间。候选接收人不进入实际负责人分布，交接确认前仍属原负责人。时长不是 SLA、劳动投入、服务故障持续时间或个人责任认定依据。

## 3. 跨组及隐私边界

历史组成员可以查询该组曾承担的区间，即使工单现已转到其他组；这不会授予当前工单详情访问权。接口不联接当前工单详情，也不返回待接收人的身份、下一责任组、OA 绑定或正文。历史页中的工单编号仅为文本，不提供绕过当前工单授权的详情深链。历史记录起点可见不等于获准查看其他组的历史区间。

人员下拉只来自本次已授权历史结果，包含已停用历史人员；不查询全部员工档案。历史名称用于当时快照展示，不代表当前通讯录健康或可以继续分派。

数据库触发器阻止两张历史表的 UPDATE/DELETE/TRUNCATE。这是应用数据库内的追加记录约束，不是防数据库所有者篡改的审计系统：现有数据库所有者仍可直接 INSERT、禁用触发器或修改函数。受监管的不可抵赖审计仍需后续最小权限数据库角色、独立日志副本及备份保护，不宣称本候选已具备这些能力。
