# 一期受控附件

本模块对应 P1-11。代码、协议夹具、真实病毒检测和企业用户验收分别记录结果；存在配置或通过 CI 均不代表真实防病毒验收已完成。附件默认关闭。

## 存储与启用条件

附件保存于 API 专用 Docker 数据卷 `itsm_attachments`，容器内固定路径 `/var/lib/itsm/attachments`。目录权限 0700，文件以随机 UUID 命名、独占创建、写入后变为 0400；没有静态文件入口。Web、worker 和数据库不挂载该卷。宿主机管理员仍有访问能力，需纳入公司运维授权与审计。

启用需在服务器私有配置中设置：

| 变量 | 要求 |
| --- | --- |
| `ENABLE_ATTACHMENTS` | 显式设置 `true` |
| `ATTACHMENT_STORAGE_APPROVAL_REF` | 存储、处理和保留规则的公司批准记录编号 |
| `ATTACHMENT_SIGNING_KEY` | 独立随机 32–64 字节的小写十六进制密钥，不放入仓库或聊天 |
| `ATTACHMENT_CLAMD_HOST` / `ATTACHMENT_CLAMD_PORT` | 内部可信 ClamAV TCP 端点，默认端口 3310 |
| `ATTACHMENT_MAX_BYTES` | 单文件上限，默认及硬上限 20971520 字节 |

ClamAV 需支持 `VERSION` 和 `INSTREAM`，病毒库日期在过去 72 小时内。扫描端口仅允许 ITSM 访问，不向用户网段开放；TCP 协议本身不提供身份认证或传输加密，跨越不可信网络前须增加受控加密隧道。扫描超时、服务不可用、病毒库过期、协议异常均拒绝放行。运维需另行部署扫描服务及病毒库更新，本应用不会自动安装或更新。

## 用户与权限

工单详情内上传、查看扫描状态和下载。支持 PNG、JPEG、PDF、UTF-8 TXT/LOG/CSV；校验扩展名、声明 MIME、内容特征、大小和 SHA-256。文本继续经过普通受理的敏感内容筛查，图片/PDF 没有 OCR 或完整 DLP，不能据此认定允许上传所有业务资料。普通附件入口不接收密码、密钥、敏感个人资料和安全事件证据。

PUBLIC 表示工单授权范围内员工可见，不是匿名或全公司公开。INTERNAL 仅限工单当前责任组的有效成员；待接收人员、申请人、代报人不会因可查看工单就取得内部附件权限。每次预留、上传、签发下载凭据和读取字节重新校验在职状态及当前权限；闭单、取消或拒绝后不接受新附件。

上传凭据有效 5 分钟，下载凭据有效 60 秒，绑定附件、操作者及操作类型，通过请求头传输，地址中不携带凭据。正式环境仍须使用 HTTPS 及真实登录。只有 CLEAN 状态可下载，响应强制作为文件保存，禁用缓存并设置 `nosniff` 和 CSP。

每个 API 进程最多同时接收 2 个上传和 4 个下载。每人滚动 24 小时预留最多 100 MiB；单工单累计预留最多 500 MiB、100 个文件，失败预留也占额度，不能靠反复失败绕过配额。浏览器哈希不依赖 secure-context WebCrypto，支持内网 HTTP 开发入口；这不替代正式 HTTPS。

## 接口与状态

| 方法与路径（前缀 `/api/v1`） | 作用 |
| --- | --- |
| `GET /tickets/:ticketId/attachments` | 当前可见文件和配置状态 |
| `POST /tickets/:ticketId/attachments/presign` | 带 `Idempotency-Key` 预留上传元数据 |
| `PUT /tickets/:ticketId/attachments/:id/content` | 原始字节上传，校验并同步扫描 |
| `POST /tickets/:ticketId/attachments/:id/download` | 签发本人短期下载请求头 |
| `GET /tickets/:ticketId/attachments/:id/content` | 重新鉴权后读取 CLEAN 文件 |

状态为 PENDING → UPLOADING → SCANNING → CLEAN/QUARANTINED；失败转 FAILED。预留重试必须使用同一幂等键和完全一致的内容；已完成上传不可覆盖。同一文件名可以对应不同附件对象。审计保存操作者、动作、请求标识及时间，不记录文件正文或签名密钥。

列表中的 `configured` 仅表示配置字段齐备，不是扫描器或存储健康证明。扫描发生在上传时，下载时验证文件摘要，不自动重新扫描；病毒库更新后的历史文件复扫尚无任务，需要启用前明确可接受的历史文件策略。

## 备份与恢复

发布备份同时生成 PostgreSQL 归档和私有 `.dump.attachments.jsonl` 字节归档，其摘要写入备份元数据。文件不可覆盖或删除，数据库快照后归档可包含新增及孤立对象。遇到正在写入或不符合私有权限的文件时备份失败，不生成通过凭据；日常备份应安排停写窗口，发布备份沿用停写流程。

归档由一次性 API 镜像容器读取数据卷，支持主 API 已停止的发布阶段。恢复验证将数据库还原到隔离临时库、文件写到隔离临时目录，核对字节摘要、清单及数据库引用，再删除验证副本；不会覆盖在线文件。缺失引用、损坏字节或摘要不符均失败，并撤销该备份旧的通过凭据。

归档以 base64 保存实际字节，约增加三分之一体积，包含隔离和孤立文件，应按敏感备份管理：私有权限、离机加密副本、受控读取及公司确认的保留期。此恢复验证不等于跨机灾难恢复或一键生产恢复，真实灾备演练需另行记录。

## 运维与验收

当前没有自动重扫、失败任务重试、删除、保留清理或管理员下载隔离文件功能。进程中断可能遗留 PENDING/UPLOADING/SCANNING，保持禁止下载；管理员先核对进程、扫描服务和审计，在批准的维护变更中处理，保留原记录，用户可新建上传。不能直接把状态改为 CLEAN。

启用前落实磁盘容量与增长告警、扫描器可用性和病毒库新鲜度告警、备份归档访问和保留规则、失败任务处置责任人。删除或保留自动化需与并发备份的快照规则一起实现，不能单独手工批量删除对象。

CI 协议夹具验证 HTTP、真实数据库、权限撤销、篡改拒绝、隔离状态和扫描故障；不证明杀毒引擎能检测恶意样本。正式试点另验真实 ClamAV 的正常文件、官方无害测试样本检测、过期病毒库和不可用故障，并核对 PUBLIC/INTERNAL 转交边界、手机上传、权限撤销和带附件备份恢复。逐项留存提交 SHA、操作者、时间、脱敏对象标识及结果，未执行项保持待验收。
