# 一期真实企业联调实施说明

此说明对应一期钉钉免登、人员同步、消息与卡片、OA 和语音入口。代码通过 CI、发布到开发机、企业接口联调及用户签收是不同交付阶段。本文不证明企业联调已经完成。

## 前置与配置

企业管理员在服务器受控配置中保存内部应用 CorpId、AppKey、AppSecret、AgentId，并授权免登、通讯录、工作通知及 OA 所需接口。凭据、员工资料、审批内容和现场证据不得提交公开仓库，也不放入聊天或命令参数。

入口必须具有手机和服务器均可信的 HTTPS 域名、证书与同源 API 转发，能够保留 Secure Cookie。不要把当前仅 HTTP 的内网入口作为手机录音验收入口；代理不缓存身份及个人数据接口，不信任客户端传入的开发身份头。

真实联调配置包括：

| 配置 | 要求 |
| --- | --- |
| `ITSM_NODE_ENV` | `production`，即使机器承担开发验证用途 |
| `ENABLE_DEV_AUTH` / `COOKIE_SECURE` | `false` / `true` |
| `ITSM_SEED_DEV_DATA` | `false`；关闭种子不会删除数据库内已有演示人员 |
| `NOTIFICATION_MODE` | `dingtalk` |
| `DINGTALK_CORP_ID` / `DINGTALK_APP_KEY` / `DINGTALK_APP_SECRET` | API 与 worker 一致，实际授权仍须企业现场核实 |
| `ITSM_PUBLIC_URL` | 可信 HTTPS 根地址，不含用户信息、路径参数或令牌 |
| `ENABLE_DIRECTORY_SYNC` / `DINGTALK_DIRECTORY_ROOTS` | 显式开关和批准的部门根 ID；首次接入保持 `DIRECTORY_RETIRE_MISSING=false` |
| `ENABLE_LIVE_NOTIFICATIONS` / `DINGTALK_AGENT_ID` | 指定试点人员后再开启；启用时必须有应用 AgentId |
| `ENABLE_LIVE_OA_APPROVAL` / `ENABLE_MANUAL_REQUEST_DELIVERY` | 显式开关，API 与 worker 一致；先核实一个低风险申请模板 |
| `ENABLE_REQUEST_INTAKE` / `REQUEST_INTAKE_CATALOG_VERSIONS` | 仅在 OA 通过后开放经过验证的确切目录版本 |
| `ENABLE_VOICE_ASR` / `ENABLE_INTAKE_AI` | 显式开关；启用时配置内部 HTTPS endpoint、model、token、`internal-approved` 数据边界及批准记录 |

关闭的模块会在就绪证据中记录为 `false`，不是已完成。配置字符串符合要求并不证明通讯录范围、模型真实路由或供应商权限正确。

## 真实管理员交接

先决定使用无演示数据的独立 UAT 数据库，还是迁移现有演示环境。当前固定发布流程使用项目 `itsm-dev` 及既有数据卷，不会自动创建第二套隔离实例；新实例需要独立完成网络、数据卷、状态目录和受控发布入口设计，不能直接复用现有状态宣称独立。

无管理员授权历史的新库：仅开启只读通讯录同步，核对两名不同真实在职员工的稳定身份；由授权管理员执行 [一次性初始化](role-administration-runbook.md)。同步不会自行授予管理权。两名管理员免登验证后，共同为第三名真实人员提案并独立批准，建立续期和交接能力。

已有任何管理员授权历史的库：初始化脚本会拒绝，包括授权已撤销或到期。不得删除授权历史、改员工身份映射或把演示身份改名成真实人员来绕过限制。先审查现有有效管理员：若真实管理员仍能登录，由其通过现有角色提案与独立复核完成交接；若只有演示管理员，必须先由系统负责人批准带外管理员迁移变更并独立核对真实身份，保留授权来源与审计，再切换真实身份。当前没有自动恢复/迁移管理员命令，因此未完成该变更前不能宣称真实环境可运营。

无论采用哪条路径，切换前须备份并验证恢复；确认至少两名真实管理员能够登录，最好有第三名用于独立复核。同步、角色、支持组成员、岗位任职和 P1 复核任命分别管理；不要从钉钉部门或职务推断授权。权限调整保留原工单与审计。

## 发布模式与证据

原 `deploy-development` / `--verify-development` 模式继续用于隔离模拟验证，会写入合成工单；真实身份环境禁止使用该模式。

新增 `deploy-enterprise-uat` 批准沿用原发布来源、审批有效期、当前 SHA、requestId 和 root 私有文件要求，同时设置：

```json
{
  "operation": "deploy-enterprise-uat",
  "verifyDevelopment": false,
  "verifyEnterpriseUat": true,
  "configurationSha256": "受控环境文件原始字节的64位小写SHA256"
}
```

这是字段示意，不是可直接使用的批准记录。管理员核对配置后固定其摘要；批准绑定确切文件内容，禁止批准后修改配置继续使用旧记录。可信工具必须由管理员审核安装，不能从发布包自动覆盖。无需扩大日常 SSH 的 sudo 权限。

经原受控入口执行批准后，发布工具使用 `deploy <SHA> --verify-enterprise-uat`。检查私有文件、生产身份配置及发布清单后，按既有流程停写、备份、迁移、启动和核对镜像。就绪检查仅执行 GET：回环就绪接口、回环与 HTTPS 的钉钉身份配置、匿名/开发身份拒绝，以及 HTTPS 页面。它不登录员工、不发消息、不发起 OA，也不调用模型。单次请求最多 10 秒，读取响应最多 64 KiB，拒绝重定向。

环境摘要在关键变更前、检查期间及完成记录前复核。配置漂移或检查失败会留下失败记录，不自动回滚数据库。备份恢复仍通过隔离临时数据库比较全部 public 表行数和内容指纹；这不证明跨机灾难恢复能力。

成功记录为 `verificationLevel=enterprise-uat-readiness`、独立的 `enterpriseReadiness`、`businessAcceptance=null`、`userAcceptance=pending`。不允许与合成业务证据混用。日常 `inspect` 复核已记录的就绪证据、当前配置摘要、容器镜像、迁移及健康；它不重新执行真实登录、HTTPS 全链路或用户操作。

回退只在迁移指纹和 Compose 兼容时允许；配置切换不由应用回退自动还原。每次配置改变需重新就绪核验并按实际状态建立新批准，不能复用已消耗的部署编号。

## 联调与验收顺序

1. 在 CI 完成本批构建、单元、隔离集成与浏览器验证，合并 main 生成不可变镜像和发布包，再集中部署。
2. 核对 HTTPS、应用权限、试点人员范围和管理员交接，关闭开发身份入口。先验证普通员工免登、无权用户拒绝及停用会话撤销。
3. 核对通讯录分页、人数、稳定身份和失败恢复，维护“服务目录 → 责任域/支持组 → 岗位 → 具体工程师”。首轮不启用缺失自动停用。
4. 对指定人员验证实际消息送达和卡片进入。卡片打开不修改工单；接单、转交及解决经本人身份与当前权限复核后回写。验证转发给无关人员无法操作。
5. 对一个申请版本验证 OA 同意、拒绝、撤销、超时和结果不明对账，再验证交付、复核与到期回收。创建成功不能替代审批结果核实。
6. 接入已批准的内部 ASR 与模型，分别用 iOS、Android 钉钉验证录音授权、取消、失败、转写和草稿修改；本人确认才建单，重复提交只产生一单。
7. 验证 SLA、P1 确认、等待恢复、员工关闭评价、敏感内容与保留策略。组织 10–20 名员工和工程师试用并签收。

逐项证据至少包含提交 SHA、配置摘要、时间、操作者、脱敏业务标识、预期/实际结果和证据位置。完整验收记录放公司受控存储；缺项保持待完成。二期监控与 CI 关联、三期安全事件按既定阶段继续，不因本批一期发布而视为完成。
