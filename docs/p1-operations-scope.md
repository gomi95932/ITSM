# 一期厂区、服务 SLA 与岗位责任操作说明

本批复用现有人员、服务组织、目录、SLA、审批、审计及通知模块。候选实现不代表已发布，也不代表企业真实人员已验收。

## 配置顺序

1. 先完成可信目录同步、真实账号登录、两名平台管理员独立授权，以及支持组成员、岗位主备和任职有效期配置。
2. 在“厂区与服务时限”维护厂区、人员归属及可服务厂区、支持组范围、岗位范围、服务范围和“服务＋厂区→主责岗位”路由。工单厂区从批准的申请人归属取得，不接受客户端自报厂区。人员的多厂区处理范围不改变其提交申请的归属厂区。
3. 每个已发布服务必须有厂区范围及每厂路由。岗位、责任域及支持组必须启用，岗位和组均覆盖厂区。标准申请必须保留批准目录中的交付支持组。
4. 首次启用前完成所有缺少厂区的历史在途工单。当前不提供历史工单批量回填功能；启用检查在提案和批准时均执行，禁止跨越该检查直接更新数据库。无厂区的已结束历史工单仍供申请人查阅，支持人员访问默认拒绝。
5. 填写变更原因，提交提案，由另一名平台管理员独立复核。复核人不能借此修改本人的人员厂区范围。只有两名管理员时，先由甲发起甲的范围变更、乙复核；再由乙发起乙的范围变更、甲复核。不得在同一提案同时更改甲乙两人的范围而使任何人都无法独立复核。
6. 启用后不能关闭隔离。历史厂区 ID 保留，可按依赖规则调整范围。变更当前范围会立即影响读取和处理资格，操作前通过在途工单列表安排交接及接管，避免无人可处理。

## 服务 SLA

在“厂区与服务时限 → SLA 模板”维护名称、启用状态、P1–P4 响应和解决/交付分钟数；在“服务 SLA”绑定服务。时限随优先级降低不能变得更短，响应不能晚于解决。无绑定的服务沿用全局优先级策略。

每个 SLA 周期保存所选模板、批准配置版本及全部目标。修改模板不会追溯改变旧周期；工单升级使用原周期的对应优先级目标，重开按当时配置创建新周期。全局服务日历和组级接单日历沿用原模块，服务模板不替代接单计时。任职变更、交接及紧急接管均不得重启 SLA 或伪造首响。

## 岗位任职与紧急接管

- 平台管理员可维护全局岗位任职；组长仅能在“岗位任职”维护其当前负责组中的任职。新增和调整复用独立复核，不允许自授任职、跨组或修改责任域/系统/岗位/目录映射。
- 任职需在职人员、当前组成员、有效岗位及有效期；启用真实钉钉通知时还需有效企业账号关联。到期、停用或撤销后，工单处理动作重新校验资格。
- 紧急撤销填写原因，立即停用任职并保存不可变记录。撤销不删除历史工单、责任区间或 SLA。已有独立批准的单工单限期继续处理授权仍按其范围执行；如需终止，应另行撤销该授权。
- 普通转交继续采用接收人确认。紧急接管由当前责任组的有效组长发起，指定同组、当前岗位和厂区合格的人员并填写理由。该操作实际改变负责人，清除待交接；待接单进入处理中，其他状态及等待期限保持。接管不代表目标本人已阅读消息或作出响应。
- 通知发给当前仍有资格的申请人、新负责人和组长；旧负责人只有仍符合当前成员及厂区资格时才接收。消息链接继续经过登录和工单权限校验。

## 验收与限制

按 `phase1-core-uat-cases.md` 的 U10/U16/U21 执行桌面、手机、直接 API、并发及重试验证。记录批准配置版本、工单责任及 SLA 周期、通知回执和审计，不使用演示人员代替真实签收。

动态人员厂区数据当前由管理员批准配置，不自动从显示名、邮箱或客户端 MAC 推断；自动权威厂区同步、历史批量回填和完整值班排班不在本批范围。真实通知、OA、企业登录及管理员交接仍需真实配置联调。
