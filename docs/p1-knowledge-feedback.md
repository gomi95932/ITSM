# 一期知识有效反馈

## 范围与状态

对应开发蓝图第 4.1 节知识页面的“有效反馈”和一期知识评价闭环。员工阅读已发布知识后，可以选择“有帮助”或“无帮助”；内容维护人员可以查看当前正式发布版本的汇总，作为修订依据。

本切片为代码候选。已编写 API、迁移、桌面/手机界面及回归用例；本机只进行静态检查，尚无此代码的 CI 运行结果、截图视觉验收、部署及业务验收证据。知识发布不等于真实钉钉入口或整个一期已验收。

## 规则

- 反馈唯一键为 `article_id + version + employee_id`，每位员工对每个发布版本仅反馈一次。修订草稿不重置旧正式版反馈；新版本正式发布后，可以对新版本重新反馈，历史记录保留。
- 身份来自当前登录会话，接口不接收员工 ID。员工必须在职，文章必须有尚未过期且未归档的正式发布版，责任组知识还要求当前组成员身份。提交和幂等重试均重新核对访问权限；不接受对草稿或已替换版本的新反馈。
- 反馈仅为布尔选项，不收集自由文本或附件。员工只收到自己的当前版本反馈；反馈接口和普通阅读接口不返回其他人员的身份、反馈明细或管理汇总。
- 知识编辑和审校人员沿用既有组范围授权，通过管理详情查看当前正式版的有帮助、无帮助和总条数。正在修订的草稿仍显示旧正式版编号及其汇总；不会将多个版本合并成一个有效率。
- 事务同时写入反馈与 `knowledge_audits` 的 `FEEDBACK` 记录，包含操作者、请求标识及幂等信息。相同请求重试不增加计数，相同幂等键改写内容报冲突，换键也不能重复投票。数据库约束和触发器保护已提交的反馈，禁止更新和删除。
- 归档、人员停用及组成员撤销不删除历史反馈。历史留存遵循后续正式的数据留存制度；本切片不提供直接删改记录的管理入口。

## 接口

`POST /api/v1/knowledge/{id}/feedback` 使用现有登录、写操作 CSRF 校验和 `Idempotency-Key` 请求头。

```json
{"version":1,"helpful":true}
```

成功返回 `200`，内容为 `version`、`helpful`、`submittedAt`。状态说明：参数或缺少幂等键为 `400`；无阅读权限、未发布、归档或过期为 `404`；已反馈、版本改变或幂等键内容冲突为 `409`；登录失效或人员停用由现有认证层拒绝。重复请求若文章仍可访问，返回原成功结果；权限撤销后不回放旧结果。

`GET /api/v1/knowledge/{id}` 增加 `feedback`，仅包含本人对当前正式版的反馈，无记录时为 `null`。

`GET /api/v1/knowledge/{id}?scope=managed` 增加 `feedbackSummary`，结构为 `version`、`total`、`helpful`、`notHelpful`，无正式版时为 `null`。管理接口不返回反馈人名单；现有编辑和审校权限仍必须满足。

## 实现与发布

- 迁移 `034_knowledge_feedback.sql` 增加 `knowledge_feedback` 及其不可变/发布版/人员/受众保护，扩展知识审计动作。既有迁移保持不变。
- API 对文章加锁，串行处理同一文章的版本变化和反馈，再锁定有效员工与必要的组成员记录，防止提交过程中归档、换版或撤权导致计数错位。
- Vue 知识详情增加反馈按钮、已反馈状态及管理汇总。请求进行时禁用重复提交；网络错误重试沿用同一操作的幂等键。已提交记录重新打开后仍可见，桌面与手机使用同一接口。
- 合并后须由既定流水线构建同一提交的后端、前端与发布包。发布前完成备份与恢复验证，通过受控迁移升级；不得只更新前端而遗漏数据库迁移。失败按发布运行手册处理，不手工删除反馈表或修改旧迁移。

## 验收

既有 Application CI 的知识集成步骤和 Playwright 用例已扩展，实际通过结果仍待取得：

| 场景 | 预期结果 |
| --- | --- |
| 草稿、未发布、过期、归档文章反馈 | 拒绝，不写反馈 |
| 非布尔选项、无效版本、伪造员工字段、缺幂等键 | 拒绝 |
| 首次反馈、同键重试、换键重复、并发重复 | 仅一条有效反馈和对应审计 |
| 两名员工分别选择相反选项 | 各自读取本人记录，管理汇总准确 |
| 修改同键请求内容 | 冲突，不覆盖原记录 |
| 修订未发布、替换正式版、旧版本页面提交 | 旧正式版反馈保留，新版本重新计数，旧页面新提交冲突 |
| 责任组受众变更、组成员撤销、人员停用 | 立即拒绝无权提交和幂等回放 |
| 数据库直接更新/删除、无权受众/旧版本/过期插入 | 数据库拒绝 |
| 桌面有帮助、重新打开、手机无帮助、维护页汇总 | 状态持久且统计一致；手机不横向溢出 |

部署后需使用正式测试员工，从钉钉入口进入已发布知识，完成阅读、反馈、重新进入、管理员汇总及撤权验证，并记录准确代码版本和验收人。隔离 CI 或容器健康不能替代这一验收。
