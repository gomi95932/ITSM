# P1-01 普通入口保护切片

日期：2026-11-10。依据 V1.1，完整 SEC 仍在第三期；本切片仅补第一期普通入口边界，不代表 P1-01 全部验收。

## 接口与行为

| 入口 | 当前行为 |
|---|---|
| POST /tickets | 必须显式 `contentClass=GENERAL`；声明和已知敏感内容检查在幂等记录、工单、SLA、事件及通知写入前执行 |
| POST /tickets/:id/actions | 所有动作携带声明；评论、原因、外协信息及验证依据使用同一检查，拒绝时不变更工单版本 |
| POST /voice/interpret | 必须携带声明；检查通过才提取本地草稿，不调用外部模型 |
| GET /intake-policy | 仅已认证人员可读取普通文本安全联络信息；不提供上传或证据提交入口 |
| GET /voice/config / POST /voice/transcribe | 录音固定关闭；转写返回 503，不调用任何转写供应商，旧 ASR 开关不能重新开放 |

`contentClass=SECURITY_SENSITIVE` 返回 403 `SECURITY_CHANNEL_REQUIRED`；缺失或未知声明返回 400 `CONTENT_DECLARATION_REQUIRED`。未知字段/结构错误仍按既有严格 schema 返回 400。旧 API 客户端必须随本切片升级，不得在后端静默默认为普通内容。

已知规则覆盖常见明文访问令牌、私钥头、带赋值的密码/密钥和部分明确安全事件描述。规则执行 NFKC 归一化，检查嵌套字段。拒绝只写 `operational_audits` 的人员、固定原因码和固定入口；不写原文、摘要、哈希、附件或业务目标 ID，不生成普通工单/Outbox 消息。检查失败不放行。

员工提交、IT 处理及文字草稿均需确认内容声明。安全联络信息以纯文本显示，不将用户填写内容拼入链接。部署管理员通过私有环境文件设置 `ITSM_SECURITY_CONTACT`，仅填写批准的值班电话/岗位/受控联络方式，不填写密码或密钥；未配置时显示线下联系信息安全负责人的兜底，不自动创建普通工单。

## 能力边界与前置条件

- 这不是 DLP、完整 SEC 或所有敏感内容的识别保证。用户误声明、变体/编码、未命中规则均可能漏检；生产还需公司 DLP、数据分级、人工培训及审计，不得宣传“完全阻止泄密”。
- 本次未扫描历史工单，也不删除/搬运既存数据。发现历史证据应由授权安全岗位按受控流程处理。
- 需指定真实安全负责人、替补与受控渠道，审批联络配置、可见范围和到岗验证；目前未用演示账号替代。
- 反向代理、APM、WAF、故障采样和主机诊断不得记录请求体/敏感查询参数；代码侧无意记录正文不代表基础设施已脱敏，服务器实际配置仍待检查。
- 附件入口、外部 AI、原始录音均不能用这套文本规则作为开放依据。附件边界和生产限流/抗滥用仍需后续切片验收。
- P1-02 个人责任、P1-03 优先级确认/失败升级、P1-04 分类兜底不因本切片提交而记为完成。
