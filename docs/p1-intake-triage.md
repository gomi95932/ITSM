状态：代码候选已通过隔离 GitHub CI，现场联调与业务验收未完成。属于 V1.1 第一期首段，不包含 REQ 审批交付、二期监控/配置项 CI 关联或三期完整 SEC。

## 交付边界

- 显式发布 `GEN-OTHER`（其他 IT 事项），只承载普通 IT 咨询/不确定分类，由服务台分诊；无效、不发布或不可见的服务编号不得静默降级。REQ 仍拒绝创建，审批矩阵未配置之前不做权限交付。
- 服务台当前责任人或未接单队列的责任组成员可纠正 INC/GEN 分类。新目录必须已发布、版本匹配、表单字段合法且对申请人与处理人均可见；跨责任组须先完成指定人员双向交接，再由接收人纠偏。保留原始目录快照及字段；分类、原因、操作者经事件/审计/出站记录；不得改变当前责任人、优先级、SLA 行或自动关闭的 `updated_at`。
- 员工主动授权在职支持人员代报，最长 7 天，可撤销。服务端从授权推导申请人。仅在该授权下创建的工单可由受托人查看或在等待补充时提交信息；不能取得既有历史工单、代签审批、确认解决、撤销/重开，也不能确认其代报的 P1。撤销、到期、员工停用或受托人不再属于支持组后失效；受托人的**独立责任组权限**不因授权撤销而丧失。
- 敏感证据仍受一期普通入口保护并留在既有安全渠道；GEN 不代表三期 SEC 已上线。授权受托人需来自有效支持组，具体代报组织策略由服务负责人审核。

## 接口与迁移

- `005_intake_triage.sql` 扩展 INC/REQ/GEN 检查约束，增加授权表、提交人、授权引用和原始目录快照；不修改历史迁移。旧工单提交人回填为原申请人。
- `GET /catalog` 显示 GEN；`POST /tickets` 可带 `delegationId`，使用真实申请人授权，幂等重放须重新检查授权；`GET /tickets?mine=true` 仅列当前有效授权下的工单。
- `GET /delegations/candidates`、`GET /delegations`、`POST /delegations`、`POST /delegations/:id/revoke` 实现候选查询、当前授权、创建和撤销。创建以客户端 UUID 作为重试身份，重复内容只记一次授权审计，撤销只记一次撤销审计。
- `POST /tickets/:id/classification` 以工单版本和幂等键提交分类纠偏；普通内容声明必须通过，保留并发冲突响应。具体字段契约见 `packages/contracts/src/index.ts`。
