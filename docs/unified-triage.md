# 统一兜底分派

## 业务规则

保留现有提单及专业自动派单流程。工单没有有效工程师邀请、尚未接单，且处于排队状态（服务申请须已通过审批）时，可进入统一具名待分派队列。未启用专业派单、缺少有效候选人、专业主备耗尽与人工邀请过期均可由补偿任务恢复到兜底。

兜底责任独立于工程师责任：负责人可查看、分类并指派其负责的工单，但不会因此获得工程师处理或管理员权限。目标工程师仍须符合现有资格校验。界面区分待分派负责人、待接单责任人与当前处理人。

主负责人超时或失效后转备用，备用仍失败则升级管理员。工作进程公平扫描每批最多 100 条，实际执行时间还取决于调度间隔和队列长度。邀请、接单、撤销和解决会结束旧兜底；旧通知按责任代次失效。工单提交时间、原始分类和 SLA 保持不变。

## 管理配置

管理员进入「派单配置 → 统一兜底分派」，搜索已同步且有效的钉钉人员，设置主负责人、备用负责人和分派超时（1–10080 个自然分钟），填写原因后保存即生效。初始未启用，不预选真实人员。

新配置只作用于新进入兜底的工单，已有积压保留原策略快照。可在积压表逐单使用「按当前配置转交」，操作包含版本校验及审计。关闭开关停止新兜底入队，既有责任继续保留，需按正常指派或显式转交处理。

负责人在「IT 工作台 → 待我分派」处理。主备均失效时管理员从积压与告警接管，不能保证在没有有效人员、工作进程不可用或数据库不可用时仍自动分派到某人。

接收策略与路由配置支持管理员直接生效并保留历史；旧 REVIEW 数据仍兼容独立复核，不改变服务申请/OA 审批规则。人工指派缺少匹配接收策略时使用 60 个自然分钟邀请窗口，已有有效策略优先，不重置原 SLA 或因其已超时而阻止指派。

## 实现位置

- `db/migrations/054_unified_triage.sql`：策略版本、责任快照、转交幂等记录、限定工单权限及配置审计视图。
- `packages/workflow/src/triage.ts`：兜底入队、完成、转备及升级，统一事务锁顺序。
- `apps/api/src/routing-config.service.ts`：管理员配置和显式转交。
- `apps/web/src/components/TriageConfigPanel.vue`：后台配置、积压和转交。
- `apps/worker/src/notification-audience.ts`：当前责任代次与有效通知接收人校验。

接口前缀 `/api/v1`：

| 方法与路径 | 权限与用途 |
| --- | --- |
| GET `/admin/routing-config/triage` | 配置管理员；配置、人员状态、积压前 200 条及总数 |
| POST `/admin/routing-config/triage` | 配置管理员；幂等保存，校验预期版本 |
| POST `/admin/routing-config/triage/transfer` | 配置管理员；幂等转交，校验工单及策略版本 |

## 验证与发布

先构建项目，再为独立测试 PostgreSQL 配置 `DB_HOST=127.0.0.1`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、控制库 `DB_NAME` 和 `ITSM_SEED_DEV_DATA=true`，运行 `node tests/integration/unified-triage.mjs`。测试账号需要创建及删除数据库的权限；测试自行创建临时库、迁移、加载合成数据并清理，不应连接业务数据库。测试包含配置并发、精确工单权限、超时与拒接、人工指派竞争、积压快照与转交、SLA 不重置及审批保护。已加入应用 CI。

发布按现有制品验证、备份、数据库迁移和 API/Worker/Web 更新流程执行。先在关闭状态验证旧流程，再由管理员明确选择真实负责人并启用。部署后核对正常直派与异常兜底两类闭环，并独立验证真实通知接收端；发送回执不能替代真实人员验收。
