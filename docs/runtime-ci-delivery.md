## 4. 业务切片衔接

按 `docs/implementation-baseline.md`，监控与配置项 CI 关联为第二期，完整 SEC 为第三期；工程 CI/CD 与上述业务分期不同。

下一批为 BASE-01 核对后补 P1-01 至 P1-04，而不是监控大屏或完整安全事件模块。静态核对显示以下缺口，仍须代码实现与测试，不可标记交付：

| 需求 | 当前缺口与验收重点 |
|---|---|
| P1-01 安全入口保护 | 普通工单、动作评论、语音草稿及转写均需统一保护；无受控接收能力不得接收敏感证据。关键词提示不能保证阻断所有安全内容；未保护通道保持关闭，交接现有受控安全渠道 |
| P1-02 个人责任 | 当前只到支持组，尚无唯一个人责任、并发接单/交接和停用兜底的完整闭环 |
| P1-03 P1 确认 | 当前矩阵直接产出 P1，尚无完整的候选确认/调整、授权主管审计和通知失败升级闭环；响应不能等待主管确认 |
| P1-04 未匹配/分类/代报 | 尚需合法事项兜底、分类纠偏和授权代报的明确契约及端到端用例 |

以上切片需先确认安全接收岗位/渠道、支持组主管与值班兜底、个人交接规则和 P1 通知升级规则。未任命具体人员时记录责任岗位，不用演示账号冒充真实业务确认。完成后依次推进 REQ/OA、INC 收尾及知识评价，再到第二期需求移交/监控试点和 PRB/CHG。
