# 主备自动派单

## 业务规则

管理员在「派单配置 → 主备自动派单」按服务启用，并设置主责、备用接收时限。前置条件是服务已经映射到有效支持组及主责岗位，人员从该岗位当前有效任职中读取。配置直接保存生效，并保留不可修改的历史版本。

跨岗位备用须在此处明确勾选「跨岗位备用（同支持组协办岗位）」。例如服务的主办岗位为岗位 A（工程师甲），协办岗位为岗位 B（工程师乙），则勾选岗位 B 作为备用岗位。工程师乙在岗位 B 的任职可保持“主处理”，本服务派单时会记录为备用候选，不需要重复创建任职。协办关系本身不等于自动备用资格，未勾选的协办岗位不自动接单。

备用岗位有多人时，可在「指定备用人员」进一步选择本服务允许的备用人员。例如岗位 B 同时有工程师乙、工程师丙，而本服务只由工程师乙备用，则只勾选工程师乙。未指定人员时按备用岗位内全部有效人员选择；指定后仅在选中人员中选择，并继续校验其来源岗位任职、支持组成员关系和厂区权限。此名单不改变主责人员的选择，也不授予人员新的权限。

1. 新工单先邀请主责人员接单，邀请期间保留当前责任组，尚未形成个人负责人。
2. 主责拒接后，在同一业务事务内邀请备用人员；主责超时或任职失效后，由后台任务转备。
3. 同一轮内，每位人员最多邀请一次；多个有效主责先于备用，顺序按任职生效时间及任职标识确定。已开始尝试备用后，不再返回主责。
   备用顺序为主办岗位内的备岗，然后是明确选择的跨岗位备用。指定备用人员时，同层级先按人员勾选顺序；再按岗位勾选顺序、岗位主处理先于备岗、任职生效时间及标识排序。所有候选必须属于本服务原支持组，并已包含在该工单创建时的服务映射快照内。
4. 接收人接受后成为实际负责人，沿用现有处理、解决、申请人确认与关闭流程。其他人员不能抢接已有候选人的邀请。
5. 候选人员全部失败后，工单保留在原支持组，产生「主备派单失败，待调度接管」路由告警，通知该组调度员、组长及有访问权限的平台管理员。由调度员安排人员接管，不擅自分配到无资格人员或其他支持组。
6. 手工取消邀请、改派或纠正分类表示调度员接管，本轮自动派单停止；需要人工继续安排。请求人取消工单同步取消尚未完成的邀请。
7. 服务申请在审批等待期间不邀请工程师；审批通过进入可处理状态后开始邀请。审批拒绝或取消后停止。

## 时限与变更边界

- 主责与备用各自配置 1～10080 自然分钟，默认显示 15 分钟。不是处理完成时限，也不是服务日历的工作分钟。
- 自动转备不重置 SLA、不增加 SLA 周期。SLA 超时仍由现有机制告警。
- 新规则默认关闭，只有启用后新提交的工单使用。已存在工单保持原派单方式。
- 每个工单保存启用时的规则版本及时限快照。后续修改或关闭规则影响新工单，不中断已有邀请；管理员可手工取消已有邀请。
- 备用岗位和指定备用人员列表也冻结在规则快照中；旧工单不会因本次升级而扩大派单范围。已经升级为路由告警的旧工单需要调度员人工接管。
- 人员有效性实时校验，覆盖在职状态、支持组成员关系、主责岗位有效任职和厂区访问范围。任职失效可触发转备。
- 后台每轮最多检查 100 个待派单工单，并按上次检查时间轮转。超时转备发生在截止时间后的调度扫描中，队列积压或后台暂停会影响实际延迟。

## 一致性与溯源

- 沿用 ticket → dispatch run 的加锁顺序；API 和调度器共享授权锁。多个后台实例通过行锁与单个待接单记录约束避免重复派单。
- 保存每次候选、来源岗位、主备身份、邀请时间、截止时间及接受/拒接/超时/失效状态。每次扫描复核来源岗位的有效任职、成员关系和厂区授权。
- 邀请、转备及升级同时写工单事件、审计与通知 outbox，业务回滚时全部回滚。
- 通知发送前复核当前候选；补充信息导致版本变化不作废有效自动邀请，转派后旧邀请不会再作为待接单通知发送给旧候选。
- 通知交由已有 outbox 投递和重试机制；消息到达不等于人员接单。实际钉钉到达验收依赖部署环境真实通知开关、应用权限和人员可见范围。

## 实施与验收

数据库迁移为 `048_automatic_dispatch.sql`。API、worker 和前端需一起发布；发布前执行现有备份与还原校验。先对人员和主备映射完整的试点服务启用，再按服务逐步开放。回退应用版本时保留新增表与历史记录，避免删除业务证据。

跨岗位备用补丁增加 `049_dispatch_backup_positions.sql`，为规则增加备用岗位及指定人员列表，为邀请增加来源岗位。旧规则列表默认为空，旧邀请来源岗位为空时按原主办岗位校验。发布后必须另行保存试点服务的备用岗位、需要时指定备用人员，并启用规则；只发布程序不会自动改变现有派单配置。

隔离集成测试入口：`node tests/integration/automatic-dispatch.mjs`。测试创建独立数据库并在退出时删除，不允许直接指向业务数据库。覆盖主责闭环、拒接转备、超时转备、两次失败升级、任职失效、人工接管、取消、规则快照、并发和幂等、通知受众、管理配置权限及审批等待边界。

上线验收必须额外确认：试点服务配置已启用；主备收到真实通知；工程师接受后后台显示实际负责人；用户确认关闭；主备失败时调度人员收到真实升级提醒。隔离数据库测试不代替真实钉钉验收。
