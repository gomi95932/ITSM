# 一期钉钉人员同步与账号停用

## 交付状态

此文档描述本分支的实现候选。数据库、接口和桌面/手机用例已纳入 GitHub 隔离 CI；实际通过结果以对应提交的 CI 为准。未完成企业钉钉权限、真实部门分页、真实员工免登及离职验收，不能按本文认定联调已完成。

## 身份、岗位与权限

- 同一企业内以 `corpId + userId` 关联人员；姓名只作为显示信息。已有 `identity_links` 继续沿用原员工 ID，保持工单、责任记录及历史审计关联。
- 新员工使用稳定的不透明内部 ID。同步仅更新姓名、部门及职务资料，不依据钉钉职务自动授权平台管理员、组长、派单员或工程师任职。
- 服务目录、责任域、岗位及具体任职继续通过已有后台配置与独立复核维护。同步后的有效员工可供支持组和任职配置选择。
- 钉钉人员的 `active`（激活状态）不能作为离职状态。未激活员工不被当作离职；本地手动停用不被同步覆盖。
- 同步停用后人员再次出现也不自动启用。管理员核实身份后显式启用，再次免登生成新会话；旧会话不能恢复。

## 配置与执行

部署环境变量（实际凭据仅留在服务器受控环境，不提交 Git）：

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `ENABLE_DIRECTORY_SYNC` | `false` | 开启后台同步；未开启不调用通讯录 |
| `DINGTALK_CORP_ID` | 空 | 与免登、通知一致的企业 |
| `DINGTALK_APP_KEY` / `DINGTALK_APP_SECRET` | 空 | 企业内部应用凭据 |
| `DINGTALK_DIRECTORY_ROOTS` | 空 | 明确授权的部门根 ID，以逗号分隔；禁止空范围 |
| `DINGTALK_PILOT_USER_IDS` | 空 | 可选试点人员 userId，逗号分隔，最多 30 人；始终限制工作通知接收人，在 `pilot` 模式下同时限制同步入库 |
| `DINGTALK_DIRECTORY_SCOPE` | `pilot` | `pilot` 沿用试点人员过滤；`authorized` 同步已授权根部门及其子部门中的全部可见员工，保留通知试点名单 |
| `DIRECTORY_RETIRE_MISSING` | `false` | 经确认后允许按缺失快照停用 |
| `DIRECTORY_MAX_REMOVAL_PERCENT` | `10` | 每次拟停用人数相对该范围现有有效人员的最大百分比 |

Worker 获取根部门、子部门和每个部门的全部人员页，去重后形成完整快照。成功间隔 5 分钟，失败重试间隔 1 分钟。分页、凭据、格式或身份冲突任一步失败，整次人员变更回滚；不会累计缺失次数。试点单轮读取超时 120 秒，授权部门模式为 15 分钟，以覆盖多部门顺序分页；最多 2000 部门、20000 人，每部门最多 1000 页。超时或超过上限均拒绝整轮更新，不截断后执行停用。

独立异步任务不会阻塞工单通知、SLA 与心跳。PostgreSQL 会话锁避免多个 Worker 重复同步；运行中断记录为失败，下次重读完整快照。

小范围联调应同时配置试点名单和应用可见范围。Worker 仍完整读取所授权部门以校验快照，但只对名单内人员入库；任何指定人员未出现在完整快照中，该轮失败，不部分导入、不累计缺失。名单变化形成新的同步范围，不停用旧范围人员。首次试点保持自动停用关闭，人员停用使用已有受控入口。

通知在检查存量队列、查询回执以及实际提交前均核对试点名单，范围外任务标记 `SKIPPED / RECIPIENT_OUTSIDE_PILOT`，不调用发送接口；取消限制也不会自动重放这些任务。该名单不授予登录或业务权限，也不代替应用可见范围、任职维护、审批配置或历史队列检查。空配置表示沿用原有范围；配置了空项、重复项、超长或超过 30 人则 Worker 拒绝启动。员工真实 ID 和名单仅保存在服务器私有配置中。

## 从三人试点扩大人员选择范围

人员选择器只搜索已同步且有效的本地员工。通知试点名单、部门根范围或应用通讯录权限中的任一限制，都可能使其他员工无法被查到。

扩大范围时先核对应用的通讯录读取权限和应用可见范围，预检企业根部门（全组织通常为 `1`）及所有子部门是否完整读取。配置 `DINGTALK_DIRECTORY_SCOPE=authorized` 和经过核实的 `DINGTALK_DIRECTORY_ROOTS`，保留 `DINGTALK_PILOT_USER_IDS` 以保持通知范围不变，保持 `DIRECTORY_RETIRE_MISSING=false`。不要通过清空通知名单来扩大通讯录。无参数执行 Worker 的 `directory-once.js` 只预检人数和部门数，加 `--apply` 才入库；定时同步使用同一范围配置。

首次成功后验证目标员工可在“服务组织”中查询、原有三人的身份和管理员权限不变、新员工没有自动获得支持组或角色权限。“人员同步”显示当前范围模式、最近同步时间和入库人数。授权部门不等于全企业；如钉钉拒绝其他部门读取，应先修正钉钉授权，再完整同步，禁止把部分结果当成全企业名单。预检通过不等于已经同步入库。

## 离职处理的条件与限制

通讯录缺失仅能说明“不在应用当前可见范围内”，不能独立证明离职。首轮接入保持自动停用关闭，验证根部门覆盖、应用权限和实际员工总量。若企业将该同步范围作为可靠在职名单，明确接受“调出应用范围即撤销 ITSM 访问”的策略后才开启 `DIRECTORY_RETIRE_MISSING`。

开启后的停用条件须同时满足：同一配置范围、连续两次成功的完整快照均缺失、未超过比例限制。首轮缺失只标记待核查；空快照拒绝全部更新，比例超限整轮回滚。变更根部门形成新范围，不自动停用旧范围人员。应用权限缩小但根部门不变仍可能产生缺失，因此变更可见范围前应关闭自动停用并复核。

停用通过已有数据库触发器在同一事务撤销全部会话，保留工单和岗位历史。此机制不等于即时 HR 离职事件：两次成功快照一般需要约 5–10 分钟，失败时会更长。紧急离职应由已授权人员直接停用 ITSM 账号，不能等待定时器；真实离职事件/HR 权威来源仍须后续联调验证。停用 ITSM 不代表已撤销 ERP、WMS 或其他业务系统权限。

## 运维与验收

平台管理员通过“人员同步”查看关联、有效、缺失及停用人数、最近成功时间和最近 20 次记录。超过 15 分钟没有成功记录显示待核查。普通员工、派单员、组长及过期管理员均不得读取此接口。页面不显示密钥或厂商原始响应。

真实联调验收必须分别留存以下证据（员工资料和现场证据不进入公开 Git 仓库）：

1. 应用权限、根部门及可见范围由管理员确认；多部门及超过一页的真实列表可完整读取。
2. 新员工同步后在钉钉免登成功，姓名变更不产生新身份；同步不授予业务处理权限。
3. 后台维护服务目录 → 岗位 → 具体钉钉人员，实际工单分配并通知目标工程师。
4. 手动停用、模拟移出已验证范围、批量范围异常分别按规则处理，旧会话立即失效，历史工单保留。
5. 人员重新出现、应用范围变化、接口超时和权限撤回均不恢复旧权限或误删人员。

隔离 CI 使用合成企业和人员验证上述本地数据库边界，不能代替真实企业联调或用户签收。
## 接口短暂故障处理

只读部门与成员查询遇到短暂网络故障、HTTP 429/502/503/504、错误码 15 或不含子错误码的 88 时，最多尝试三次。带子错误码的权限错误、格式错误立即失败；整轮读取不完整时不导入部分人员。
