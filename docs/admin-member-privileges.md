# 管理员成员权限配置设计与权限入口核查

日期：2026-11-24。本说明对应代码候选；代码验证、部署和真人验收分别记录，不混用结论。

## 目标与维护方式

管理员可自行调整人员与既有权限的对应关系，不再通过代码、种子文件或数据库维护脚本任命 P1 复核人及同类业务人员。复用现有支持组、真实员工和授权表，不新增一套独立身份或通用权限引擎。

入口：“支持组 → 支持组与成员 → 选择支持组 → 员工行盾牌按钮”。界面名称为“成员权限”。管理员勾选权限、填写依据，确认内容边界后“保存并生效”；可重新读取当前值。未修改内容、未填依据或未确认内容边界时，保存按钮禁用。

目标员工须为有效员工且已加入启用的支持组。人员仍来自可信钉钉通讯录；需要新任职时，使用现有“岗位任职”维护人员与岗位关系。授权按当前数据库状态校验，不信任前端隐藏或已登录会话中的旧权限。

业务岗位名称、人员和映射可配置。权限动作的语义仍由程序定义，例如“P1 复核”对应哪些接口；新增一种系统尚未实现的业务动作仍需开发。管理员日常更换人员、增减授权无需改代码。管理员身份不自动代替 OA 业务审批人、知识独立审校人或工单申请人。

## 业务约束

1. 管理员直接保存成员权限，无“提交后等待另一管理员复核”。可为自己配置资格，执行具体业务时仍检查独立性。
2. P1 复核人不得复核本人申请、代提或本人调整优先级的工单。撤销最后一名有效复核人被拒绝；待处理 P1 还须保留符合独立性要求的有效复核人。
3. 知识作者不得审校本人文章，审校人不得发布本人审校的文章。撤销编辑或审校资格导致未完成文章无人承接时拒绝保存，先处理文章或完成接替。
4. 目录发布勾选列表只展示当前支持组的申请类服务，拒绝伪造其他组编码或故障类服务编码。服务目录发布沿用既有按服务编码授权，不修改已有发布业务逻辑。
5. 一次保存原子更新成员的全部勾选项，保留其他支持组的权限。不会顺带新增角色、岗位任职或支持组成员，不改历史工单责任、优先级结果及 SLA。
6. 未设置起止时间的这四项授权持续至撤销，员工停用后业务接口拒绝其使用。既有角色和岗位任职的有效期继续在各自页面配置。

## 接口与数据

- `GET /api/v1/admin/support-structure/groups/:group/members/:employee/privileges`：返回组版本、员工状态、当前权限及可配置服务。
- 同路径 `POST`：提交 UUID、预期组版本、权限集合、服务编码集合、依据和内容分类。使用现有登录、CSRF、内容边界和平台管理员校验。
- 复用 `priority_reviewers`、`knowledge_editors`、`knowledge_reviewers`、`request_catalog_publishers`。
- 迁移 `052_member_privileges.sql` 新增不可变 `member_privilege_audits`，扩展统一操作日志视图，记录真实执行者、目标组、目标人、前后权限、依据、时间及请求标识。不修改既有迁移或既有授权记录。
- UUID 支持同人同内容重试；不同内容或不同执行者复用 UUID 拒绝。组版本冲突提示重新读取，避免两位管理员互相覆盖。
- 授权变更使用现有权限事务锁，P1、知识和目录业务操作与撤权串行校验。撤权提交后的新操作立即按新权限判断。

## 验收清单

- 管理员查看、授予、读取及撤销四类权限，范围互不串组；保存后列表徽标更新。
- 普通员工、普通工程师、过期或停用管理员无法调用管理接口。
- 失效员工、未入组人员、非法服务编码、重复值和未知权限被拒绝，失败不产生部分变更。
- 重复请求只执行一次；并发编辑一个成功、另一个版本冲突；审计记录不可更新和删除。
- 使用真实业务服务验证 P1 本人复核被拒、独立复核可通过，知识编写→独立审校→发布可闭环；撤权后新操作被拒。
- 校验待复核 P1、待审知识及未完成知识编辑的连续性保护。
- 浏览器验证保存条件、读取已保存权限、撤权、统一日志、桌面及手机宽度与键盘焦点。
