# 一期服务组织配置实现说明

更新日期：2026-11-23。范围：BASE-01、P1-02、P1-10、R1a/R1b。状态：代码候选，须以同一提交的 CI 结果核验，不代表已部署或真实钉钉已验收。

最新规则：有效平台管理员在角色授权、支持组、服务组织和岗位任职页面直接保存并生效，可配置本人，无需另一名管理员复核。普通组长仍使用限定本组的提案与独立复核。本文后续历史候选章节中的独立复核描述，涉及上述四类管理员配置时以本规则为准；OA 业务审批、交付复核、P1 确认、逐单继续处理授权及其他配置流程不随本次调整。操作见 `admin-configuration-guide.md`。

## 产品规则

当前 IT 基础设施运维、信息系统运维及 Helpdesk/网络/系统/资产、ERP/SRM/WMS/OA/AGV/PDM/COST/HUB/TB/钉钉/邮件仅为初始化输入。责任域不是固定两个；管理员可配置第三个乃至更多责任域、业务系统、岗位、任职人员和服务映射，无需修改代码或重新部署。初始组织模板已有页面候选，正式初始化发布和真实人员确认仍待现场完成，不能把演示人员作为实际任命。

岗位是业务职责，支持组是授权和队列边界，权限角色是允许执行的动作，三者不合并。员工从受信员工目录选择，钉钉关联使用既有企业 ID 与用户 ID，不按姓名推断身份。真正开启钉钉发送时，发布任职配置须具备本企业的身份关联；此校验不等于已经验证应用可见范围或真实送达。

已发布记录不物理删除，使用停用和重新启用实现业务增减。停用前检查启用的子项和引用关系，冲突则要求一并调整。草稿、待复核变更不影响当前工单；基线版本冲突返回 409，不能覆盖别人已发布的修改。

## 当前代码候选

| 对象 | 管理与行为 |
| --- | --- |
| 责任域 | 自定义新增、改名、停用和重新启用，不限制为初始两域 |
| 业务系统 | 关联责任域；新增、改名、停用和重新启用 |
| 岗位 | 关联责任域和既有支持组；主办/协办配置不直接赋予权限 |
| 任职 | 受信员工、主处理或备岗、生效和截止时间；一岗多人、一人多岗；同人同岗有效期不重叠 |
| 服务映射 | 针对既有或本次新建服务项设置责任域、系统、唯一主办及协办岗位；主办组与目录默认组必须一致 |
| 服务目录 | 新建 INC/标准 REQ，维护名称、描述、可见组、展示顺序、受控表单字段；管理员与岗位路由一起直接原子发布 |
| 发布 | 预览候选、说明理由、管理员直接保存、版本竞争控制、原子发布与不可变审计 |
| 工单 | 新单保存路由版本/岗位快照；领取、指定候选、交接和候选通知重新检查当前任职资格 |
| 失效 | 无效待接收邀请撤销；配置岗位无人覆盖时产生告警，不越过岗位静默转给其他人 |

岗位任职不等于接单：邀请、本人接收和实际责任人仍分别记录。配置变更不会改写旧单的配置快照、负责人和 SLA；本次候选增加任职失效后的处理阻断、主管发起交接及独立复核的逐单限期授权，具体边界见“工单责任连续性候选”。不得把保留旧负责人理解为仍可无限期继续处理。

## 管理员自主配置基线（2026-11-23 补充）

平台提供通用的人员、支持组、岗位、服务目录及关联框架。具体名称、人员数量和映射关系由管理员在后台维护；当前基础设施、信息系统及各应用清单只是初始配置，不是代码枚举。新增业务系统、调整职责、增减工程师或更换负责人不应要求开发修改代码、执行 SQL 或重新部署。配置发布复用现有预览、版本及审计机制，新增管理员直接保存路径，审计标记 `ADMIN_DIRECT`，不冒充独立复核。

| 管理对象 | 管理员可配置的业务内容 | 现有入口与边界 |
| --- | --- | --- |
| 工程师人员 | 从有效员工中增加或移除工程师资格，调整所属支持组、岗位及任职有效期 | “人员同步”查看同步统计和记录；人员选择在配置表单中完成，来自可信目录；“支持组”维护成员 |
| 支持组 | 新增、改名、调整说明、维护成员、停用及恢复 | “支持组”；作为授权和工单队列边界 |
| 责任域与业务系统 | 自定义增减和改名，调整系统所属责任域 | “服务组织 → 责任域 / 业务系统”；历史对象通过停用实现减少 |
| 岗位 | 自定义名称、所属责任域和支持组、启用状态 | “服务组织 → 岗位”；Helpdesk、网络、ERP 等为可修改初始值 |
| 人员与岗位关系 | 一人多岗、一岗多人、主责或备岗、开始及结束时间、撤销任职 | “岗位任职”或“服务组织 → 任职人员”；管理员可选择有效员工，保存时自动补齐目标支持组成员关系并留痕 |
| 服务内容 | 新增及维护服务名称、说明、工单类型、表单、可见范围和展示顺序 | “服务组织 → 目录维护”；标准 REQ 继续遵守现有审批与交付要求 |
| 服务与岗位关系 | 每个服务设置唯一主办岗位及协办岗位，关联责任域和可选业务系统 | “服务组织 → 服务映射”；多个服务可复用同一岗位，不为每名人员重复建服务 |
| 派单与服务承诺 | 按已实现范围维护接单时限、兜底组、服务日历及 SLA 模板 | 复用对应配置入口，不因增加岗位或人员复制一套派单引擎 |

有效候选由“服务目录 → 服务映射 → 主办岗位 → 当前有效任职人员”计算，并同时核验员工状态、支持组资格及启用时适用的厂区范围。多名工程师符合条件时继续使用现有派单和确认接收机制，不能仅凭人员排列顺序认定责任人。管理员配置的是候选范围；具体工单在接收或受控接管后落实到一名负责人。

例如，可将“ERP 无法登录”和“ERP 打印异常”均配置到“ERP 运维工程师”岗位；该岗位任职人员从甲调整为乙时，管理员维护任职关系及必要的支持组资格即可，两个服务映射无需分别改人。示例不构成实际任命。

### 人员与关系增减规则

1. 新增工程师：确认钉钉员工已同步，选择人员并配置有效岗位任职，检查服务映射并预览候选；管理员直接保存生效，再验收新单路由。支持组成员资格可手工维护，也会在管理员任职保存时自动补齐。已有映射可复用。
2. 更换人员：先建立接替人的资格与有效任职，再停止原任职；检查在办单、待接收、审批、交付和知识等责任。新单按当前配置路由，旧单通过原有交接流程处理，不能改写历史负责人或 SLA。
3. 减少岗位或服务：先查看引用和覆盖情况，迁移或停用依赖，再提交停用；不能留下启用服务无人负责或指向失效岗位。保留名称、稳定标识、历史版本及工单引用。
4. 移除工程师：撤销任职和支持组资格，不等同员工离职；员工仍可作为申请人正常使用其获准服务。实际离职由可信人员源停用账号并撤销会话，不能以删除历史员工记录代替。
5. 变更生效：管理员保存时重查权限、人员、依赖及版本，在同一事务内生效；组长提案仍待独立复核。紧急任职撤销沿用现有立即撤销入口并保留原因及审计。配置变更不向未获准范围发送通知。

### 已有能力与剩余差异

上述核心配置已有本地页面、API 及版本存储实现，应复用现有模块。代码存在、CI 通过、服务器发布和管理员实际配置验收分别记录，不能相互替代。

- 人员同步页面目前仅提供状态、数量和记录查询，不提供创建企业员工或主动同步按钮。钉钉全员可见范围和目录同步范围仍需单独配置与验收；扩大应用可见范围不能代替完成同步。
- 当前入口分布在“支持组”“岗位任职”“服务组织”等页面。后续可统一为服务组织管理导航及快捷操作，复用相同接口和数据，不建立第二份人员或映射库。
- 按最新简化要求，管理员可直接配置本人或其他有效员工的支持组、岗位和权限角色；不再要求第二人批准。旧提案与组长路径保留独立复核。本次不放宽业务自批、P1 确认或工单数据读取边界。
- 当前有单项依赖检查、逐单交接及责任连续性机制，但没有统一的一键人员退出与批量责任交接向导。未实现前应展示并按业务入口逐项办理，不承诺停用后全部业务责任已自动转移。
- 当前组织配置采用整份版本发布，支持对象数量及载荷大小有上限；扩大人员与服务规模前核对容量。大批量导入、批量编辑和完整值班排班不计为已实现。

本基线纳入一期 P1-02 验收；执行用例见 `phase1-core-uat-cases.md` 的 CFG-01 至 CFG-07。

## 存储与 API

蓝图中的责任域、系统、岗位、任职和映射为逻辑实体。当前物理实现使用迁移 `017_service_structure.sql`：整份配置以不可变 JSON 版本发布，当前版本指针在同一事务切换；关系视图 `service_domains`、`business_systems`、`support_positions`、`position_appointments`、`service_position_routes` 用于资格查询。这是对概念表的物理实现选择，不是另建一套可直接写入的同名实体表。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/admin/service-structure` | 当前版本、配置、可选支持组/服务和最近变更 |
| `GET /api/v1/admin/service-structure/catalog` | 目录维护清单、表单版本、审批策略与发布人资格；最多 500 项并标记截断 |
| `GET /api/v1/admin/service-structure/people?q=...` | 受限查询有效员工和已有身份关联状态 |
| `POST /api/v1/admin/service-structure/preview` | 校验完整草稿、预览实际有效候选和告警 |
| `POST /api/v1/admin/service-structure` | 创建幂等变更提案，不改变生效版本 |
| `POST /api/v1/admin/service-structure/apply` | 仅平台管理员：校验并原子发布服务组织与目录，必要时补齐成员 |
| `POST /api/v1/admin/service-structure/appointments/apply` | 仅平台管理员：直接保存岗位任职 |
| `POST /api/v1/admin/role-bindings/apply` | 仅平台管理员：直接配置权限角色及有效期 |
| `POST /api/v1/admin/support-structure/apply` | 仅平台管理员：直接维护支持组与成员 |
| `POST /api/v1/admin/service-structure/{id}/review` | 独立批准或拒绝；批准重新核验权限和完整关联 |
| `GET /api/v1/admin/service-structure/{id}/history` | 变更审计 |
| `GET /api/v1/tickets/{id}/assignment-candidates?groupId=...` | 按该工单快照及当前任职筛选候选人，不暴露全员通讯录 |

以上为当前代码接口；蓝图列出的分实体 CRUD 是目标交互契约，不应宣称这些其他路径已经存在。整份配置有容量上限，正式试点前应确认实际规模；不适合无限制嵌入员工目录。当前全量提案适合首期小规模配置，规模增长后可保留版本语义并拆分查询/编辑接口。

## 支持组及成员后台候选

新增导航“支持组”，仅有效平台管理员或支持组长可见。管理员可提出新增/修改组；组长仅可查看自己负责的组并提出成员调整。成员从受信有效员工搜索选择，组成员、业务岗位和权限角色分别维护，不因加入组而自动获得管理角色。

页面包含组内成员查询及每页 50 人分页、角色/附加授权提示、组和成员变更提案、独立管理员批准/拒绝、不可变审计及变更前后快照。支持组及提案当前各返回前 200 条，页面明确提示清单截断，不宣称已实现完整分页。组停用及恢复已在后续代码补齐，见“整组停用与恢复候选”；不提供物理删除历史记录。

任何成员移除仍须通过后台责任连续性检查：未结工单、交付、知识责任、有效或未来任职、末位成员/组长/P1 复核人等条件不满足时不生效。移除已批准后撤销组范围内的相关授权；失败保留提案及输入供处置后重试或拒绝，版本冲突要求刷新重提。提案人和涉及员工不能复核自己的变更。

接口响应新增显式 `canManageGroups` 能力，与 `canReview` 分开提供；不依赖按钮隐藏作为权限边界。新增集成覆盖组长范围、搜索分页、并发版本及普通员工隔离，浏览器覆盖组新增/改名、成员添加/移除、禁止自审、末位成员保护及桌面/手机审计。本节新增测试须以包含这些改动的最终提交 CI 为证；旧运行不能证明本次页面已通过。

## 目录与路由联动候选

“服务组织 → 目录维护”增加新建和编辑服务项。责任域、系统、岗位、任职与新服务路由可在一份草稿内配置，经同一提案独立复核；目录元数据、表单版本、不可变目录快照和服务组织版本在一个数据库事务生效。复核页面展示目录状态、字段、可见组、顺序、审批策略和首位发布人任命，不能只看到组织配置却批准隐藏的目录改动。

新建标准 REQ 必须显式任命提交人为首位目录发布人，且其为默认支持组的在职成员；既有 REQ 仍校验显式发布人授权，批准时重新检查。既有 OA 模板和审批职责可维护，但没有实际 OA 接通时仍禁止创建真实 REQ 工单。审批矩阵不自动赋予平台权限。

迁移 `018_service_catalog_bundle.sql` 新增排序、提案目录变更/基线快照和不可变目录修订记录。并发保护同时核对组织版本、表单版本和当前目录基线；旧接口撤回发布即使未改变表单版本，也会让待复核目录提案失效。旧 REQ 发布接口不得单独把默认组改成与启用岗位映射不同的组。

已发布目录通过停用和重新启用增减，不抹除历史。表单字段采用受控文本/选项模型，不提供任意脚本执行。每份提案最多携带一个目录项变更，可同时包含关联的组织配置；当前不是跨多个目录项的批量编辑工具。目录可见范围目前按支持组配置，尚不等于完整组织/厂区策略。每目录独立 SLA 模板选择和离转岗逐单授权仍待完成；整组停用依赖处理见下节，不提供自动迁移。

本候选增加策略单元测试、隔离数据库集成测试和桌面/手机浏览器测试，覆盖新增域/系统/岗位/人员/目录到员工报单、停用/恢复、版本竞争、历史快照、审批发布人撤权和 OA 关闭边界。新增测试结果须以本次最终提交 CI 为准，不能沿用此前支持组 UI 的成功运行。

## 初始组织模板候选

“服务组织”工具栏增加“初始组织模板”。管理员选择需要的责任域及各自的既有支持组，预览新增清单后加入当前配置草稿。当前模板包含 2 个责任域、11 个业务系统和 15 个岗位，采用稳定的 `tpl-` 编码；只是可选起点，不限制后续自定义域、系统或岗位，也不在迁移或应用启动时自动装载。

新增项默认停用。模板不创建任职、钉钉身份、服务目录、审批策略或分派路由，不修改既有 GPU/AI 等服务；真实人员和服务需另行配置，经过原有预览、独立复核及版本检查后发布。没有额外的模板发布接口或绕过审批的数据库写入路径。模板导入页面只生成内存草稿，取消不改变任何配置；加入草稿后仍可整体放弃。

重复导入保留同编码对象的自定义名称、状态和岗位支持组，不恢复停用项、不覆盖既有任职和映射。同名不同编码或同编码但所属责任域不同的记录，阻止整次导入并提示冲突；不按名字猜测合并历史身份，不出现只导入一半的草稿。所选支持组必须实际存在，最终发布仍以服务端校验为准。模板条目和合并函数位于 contracts 包，只提供初始建议数据，不作为服务端可接受责任域/系统/岗位的枚举。

本候选补充策略单元测试及桌面/手机浏览器用例，检查模板数量、分域选择、重复导入、自定义改名保护、冲突原子性、无实际人员或路由的默认边界，以及草稿到独立发布的完整路径。是否通过须核对包含这些改动的最终提交 CI；本节不代表 B23 全部服务样例、真实人员初始化或一期验收完成。

## 支持组生命周期候选

支持组页面新增停用和恢复入口，由平台管理员提案、另一名平台管理员独立复核；组长不能整组停用或恢复。新增 `GROUP_DISABLE`、`GROUP_RESTORE` 提案类型和迁移 `019_support_group_lifecycle.sql`，不改写已执行迁移。停用/恢复使用原有配置版本、幂等键、授权事务锁及不可变审计。

`GET /api/v1/admin/support-structure/groups/{group}/dependencies` 仅对平台管理员开放。按九类展示总数和最多 100 条引用：未结工单（包括待接收目标组）、待完成审批/交付创建、未完成交付或尚未回收授权、未归档知识（含已发布知识）、启用岗位、启用任职、已发布目录的默认组/可见组、出入方向兜底关系、启用分派策略。各类别明确标记是否截断，不将前 100 条误报为全量。历史关闭工单、归档知识和已停用组织记录保留，不因停组被删除。

有阻塞依赖时不能提交停用；提交后增加依赖，批准时也重新检查并拒绝，失败事务不撤权、不清成员。依赖需在原业务入口显式交接、归档或经复核调整配置；岗位与任职需停用，目录需撤下或修改其引用，兜底关系与分派策略需先调整。不是“一键把所有责任转给另一组”。

批准停用在单一事务内保存成员、P1/知识权限、目录发布人和组内角色快照，逐项撤销待复核及生效中的组内角色并写角色审计，移除成员和组内专项权限，再标记支持组停用。全局平台管理员权限、员工身份及其他组权限不受影响。不能向停用组增加成员、启用岗位、发布目录或配置分派/兜底；待复核路由在批准时重查状态，仍允许拒绝过时提案。数据库运行时护栏阻止已停用组被重新用于新工单、成员、知识、审批队列、交付、角色、目录和启用分派策略，组行锁与停用事务串行。

恢复仅重新启用组，不恢复旧成员、专项权限、角色授权、岗位、目录或路由。人员与权限需重新任命并走既有复核。服务组织编辑保留停用组的历史选择标签和停用岗位引用，不能因隐藏下拉项而迫使删除历史；初始模板不能将新岗位导入停用组。停用不改写任何既有工单或 SLA。

新增单元、隔离数据库集成和桌面/手机浏览器测试，覆盖停用/恢复、独立复核、组长范围、依赖二次核验、失败原子性、撤权审计、归档引用、运行时护栏及历史保护。须以最终提交的完整 CI 为准，本节不是服务器已发布证明。批量责任迁移和真实钉钉/ OA 验收仍不在本候选的完成范围内；逐单继续处理授权另见下节。

## 工单责任连续性候选

迁移 `020_ticket_continuity.sql` 为工单增加责任代次及逐单授权记录。岗位、责任域或任职失效后，API 即时重算处理资格，拒绝原负责人的补充请求、等待厂商、提交解决方案及分类纠偏；不依赖异步扫描才能撤权。工单负责人、状态、原路由快照和 SLA 不被配置发布静默改写，负责人仍可发起正常交接。后台扫描将需处理的责任缺口提交给当前责任组主管。

当前责任组的有效组长可发起逐单交接，指定接收组和符合当前任职条件的接收人。仅被指定的人可以确认接收；确认前不替换原负责人，不伪造人工响应，不重置 SLA。普通工程师或仅有调度角色的人员不能使用主管交接能力。

原负责人或当前责任组组长可提议继续处理原单，填写理由和最长 7 天的截止时间。须由另一名有效组长独立复核，复核人不能是提案人或被授权人。授权限定到工单、员工、支持组和责任代次，不恢复岗位任职或新单领取资格；到期即时失效，主管可提前撤销。账号停用、移出支持组不受此例外绕过。责任人或责任组变更、分类路由快照改变会推进责任代次，之后即使转回原人，旧授权也不能复活。

提案、批准、拒绝、撤销、主管交接与本人接收均走工单版本、幂等、授权锁、不可变事件/审计和通知队列；内部授权详情不向普通申请人展示。此候选覆盖普通工单处理和分类纠偏，不代表 REQ 交付、知识维护等所有离转岗责任已全面覆盖。未实现批量交接，也不代表真实钉钉通知、OA 或企业人员初始化已经完成。

新增单元、数据库集成和桌面/手机浏览器回归，覆盖即时阻断、独立复核与越权拒绝、并发批准、到期和撤销、确认交接、旧授权不复活、账号/成员边界及 SLA 不变。仍以包含本候选的同一 SHA 完整 GitHub CI 为准。
