# 一期等待原因与跟进

## 范围及状态

对应 P1-08/P1-09/P1-13/R3/R5，遵守 V1.2 第 2.4 节。本文记录代码候选，不代表 CI、部署或现场验收通过。REQ 保持关闭，测试申请仅在隔离 GitHub CI 内构造，无真实 OA 或权限开通。

## 操作与责任

| 操作 | 必填 | 时钟及责任 |
| --- | --- | --- |
| 请求用户补充 | 问题、用户等待原因、未来补充截止时间 | 暂停解决时钟，不暂停首响；原负责人继续负责 |
| 等待厂商 | 跟进内容、厂商原因、厂商工单号、跟进负责人、未来跟进时间 | 不暂停 SLA；原负责人继续负责 |
| 用户补充 | 补充内容 | 恢复处理中及解决时钟，清除当前等待元数据 |
| 恢复厂商等待 | 继续处理说明 | 仅当前具备岗位或有效接续资格的实际负责人，将厂商等待恢复为处理中；清除等待字段，保留原负责人和全部 SLA 记录 |
| 交接 | 遵循既有待接收及实际接收规则 | 接收前责任不转移；接收后保留本次等待起止及截止时间 |
| 离开等待状态 | 遵循原有解决/交付门槛 | 清除当前等待字段，事件及审计仍保留 |

发布后合成验收候选 `phase1-waiting-v2` 将厂商恢复、原申请人越权拒绝、空说明拒绝、重放、SLA 保持及再次进入等待纳入同一张 INC 工单。发布包演练必须检查新增验收项；代码和故障注入用例尚待本候选同 SHA 的实际 CI，不沿用旧档案的成功结果。

原因代码为 `USER_INFORMATION`、`USER_AVAILABILITY`、`VENDOR_SUPPORT`、`VENDOR_PARTS`、`VENDOR_CHANGE`。前两项只能用于用户等待，后三项只能用于厂商等待。仅当前具备处理资格的实际负责人可发起；等待不能绕过岗位、个人责任、REQ 交付及独立复核门槛。

## 数据和 API

- 迁移 `032_ticket_waiting.sql` 在 tickets 增加 `waiting_reason_code`、`waiting_since`、`waiting_due_at`。允许存量全空，禁止部分填写、不匹配原因、非有限时间或截止不晚于起点。
- 等待开始及未来期限校验使用数据库时钟，客户端只提交规范 UTC ISO 截止时间。无效输入回滚幂等预留及所有业务写入。
- `POST /api/v1/tickets/:id/actions` 的等待操作增加 `waitingReason`，厂商等待也必须有 `dueAt`；其他操作禁止注入等待原因。旧客户端需要同步更新，不能用缺省原因猜测用户意图。
- 状态、版本、等待信息、SLA、事件、审计与 outbox 同事务提交。幂等重放不制造第二次等待；并发不同操作仍遵守版本与行锁。
- `RESUME_VENDOR` 仅允许 `WAITING_VENDOR → IN_PROGRESS`，必须有非空说明；原负责人已交出责任、待接收人员、申请人、无有效岗位或已失效接续授权者均不得操作。不要求 REQ 已满足交付完成条件，因为恢复处理并非交付完成；后续解决仍受原有交付及独立复核门槛约束。操作不创建新 SLA 周期、不记首次响应、不暂停或重置时钟，并记录事件、审计及进度通知。
- 详情返回 `waiting`。非等待返回 null；存量等待返回 `UNRECORDED`，起点、期限、是否到期均为 null，不把未知当未逾期。
- BEFORE 触发器在离开等待时清理字段；原始 SQL 只切换等待类型而不改元数据时降为未知，不沿用旧类型原因。此规则不替代受控 API 或数据库权限管理。

## 展示和统计

详情展示原因、开始、截止及是否已到期；两种等待表单提供对应原因下拉框和日期时间输入。符合资格的厂商等待负责人可使用“恢复处理”，填写“继续处理说明”；员工端可查看“已恢复处理”进度。进度消息只发申请人和当前负责人，内容不携带说明、厂商工单号或证据。报表沿用当前责任组、上海创建日期窗口、INC/REQ 分开及个人/服务筛选，增加等待原因分布、跟进已到期数及未记录数；不返回厂商单号、正文或外部证据。

统计是当前状态快照，不是所有历史等待次数、历史原因区间或工程师工时。历史责任区间继续使用已有独立口径，不以当前原因回填过去。跟进到期不等于 SLA 违约，不自动关闭、不自动取消申请、不自动分派他人。

## 到期催办候选

- 迁移 `033_waiting_follow_up.sql` 增加不可变催办信号。Worker 按数据库时钟扫描已到期、元数据完整且责任组有效的当前等待，每批最多 100 单；使用工单行锁及 `SKIP LOCKED`，按工单、组、等待开始、期限与原因去重。信号直接复制数据库原始时间精度，不用 JavaScript 毫秒时间回写去重键。
- 信号、事件、审计、通知 outbox 同事务提交；任一写入失败全部回滚。催办不修改工单业务版本、当前状态、个人责任、SLA 或责任历史。不推定存量未知等待的到期时间。
- 用户补充到期只通知当前在职申请人、具备当前岗位或有效接续资格的实际负责人。厂商跟进到期不通知申请人。负责人缺失或失去资格时，内部催办转给当前组的有效组长；不广播全组、不发给待接收候选人，也不因为有平台管理员角色就获得工单内容。
- 扩展收件人与发送前均重新核验资格。同组接收交接后使用当前负责人；跨组交接、离开等待、原因/开始/期限变化均使旧信号立即失去发送资格。每分钟复查已扩展的有效信号，每批最多 20 个，为后来接任或补齐任命的合格人员追加通知；不重置已有 `DELIVERED`、`DEAD`、`SKIPPED` 或不明发送结果。
- 发送沿用现有持久化检查点、明确失败重试、结果不明待核查、通知失败工作台及组内授权人工重试。通知只包含单号、到期提示和 HTTPS 授权详情链接，不携带问题正文、厂商单号、审批内容或外部证据。提醒送达也不算首次人工响应。
- 当前策略为每个等待期限一次到期提醒，不制造周期轰炸、自动关单或未经批准的升级链；厂商需要再次跟进时，由有权限的负责人先登记恢复处理，再发起带新未来期限的厂商等待，保留两次操作记录。用户等待期限直接延期尚未实现，不宣称可在原状态编辑期限。真实消息送达和现场任命仍待验收。

## 验证与遗留

- API 单元候选：原因匹配、规范期限、数据库快照时钟及未知值；报表候选：分布、到期、未知及空集。
- 隔离集成候选：无效输入全事务回滚、同键并发重放、越权、用户仅暂停解决、厂商不暂停、接收交接保留等待、到期与 SLA 分离、报表范围/隐私、数据库约束与触发器。
- Playwright 候选：桌面及手机实际提交、用户补充、厂商等待、到期展示、报表未知值与横向不溢出；证据 `waiting-detail-{desktop,mobile}.png`、`waiting-reports-{desktop,mobile}.png`。
- 恢复处理新增候选：状态与必填校验、当前责任及待接收边界、有效接续授权/撤销/到期、并发同键只提交一次、旧版本和重复转换回滚、等待字段清除、全部 SLA 行不变、事件审计 outbox 完整及新等待期限；桌面/手机覆盖员工不可操作、说明必填、恢复后时间线和再次等待。以上均需同 SHA 的实际 CI 执行证明。
- Worker 单元候选：事件/信号/审计/outbox 的提交、任一步失败回滚及连接释放；集成候选 `waiting-follow-up.mjs` 在真实 PostgreSQL 验证期限精度、用户/厂商收件人、任命/成员/离职/组长撤权、待交接与接收交接、旧信号失效、发送前撤权、催办不算首响、去重与并发跳锁、扫描和收件人补偿批量上限、失败整批回滚。
- 等待催办集成步骤临时停止隔离 CI 的后台 Worker，使用同一镜像的一次性测试容器执行生产模块，然后无论成败恢复 Worker。钉钉提供方为进程内桩，不访问外部服务；并发用例仅提交合成数据，不在开发机执行。
- 自动催办已有代码和测试候选，但尚未通过本修改同 SHA 的实际 CI，不记为已验收。结构化历史等待原因区间仍未实现。真实钉钉送达、公司 SLA 日历、现场责任映射与集中验收仍待完成。
- 本机仅编辑及静态检查；以上执行证据必须引用同 SHA 的实际 CI 结果，不能以新增测试文件代替通过证明。
