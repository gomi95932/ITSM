# P1-05 REQ 目录版本与审批矩阵

状态：代码候选，隔离 CI、现场联调和业务验收待核实。P1-06 OA 与 P1-07 交付尚未实现；REQ 对员工保持关闭。

## 范围与控制

- `006_request_catalog.sql` 增加按服务项显式任命的发布人、不可变目录版本和发布/下线审计。生产默认没有发布人；CI 测试单独创建任命，不以支持组成员身份自动赋权。
- 管理接口 `GET /request-catalog/:code/versions`、`POST /request-catalog/:code/versions`、`POST /request-catalog/:code/unpublish` 仅允许在职且被任命的发布人，写入还要求会话 CSRF、幂等键、预期版本和普通内容声明。目录版本保留表单字段、可见组、责任组、OA 模板引用及分步审批角色；管理员可下线当前版本，但不能改写历史版本。
- 发布前校验组、静态审批人、表单字段、审批链和有效期上限（1 至 3650 天）；动态主管的真实解析在 P1-06 接入人员主数据时验证。策略发布只准备配置，不开放 REQ 提交。现有 `POST /tickets` 仍拒绝 REQ，员工目录继续显示“暂未开放”，避免审批与交付状态机未完成时绕过审批。
- 历史占位目录在首次变更时归档当前版本。审批模板 ID 是引用，不是凭据；禁止把密钥或安全事件证据作为目录说明保存。

## 验证与下一步

- `tests/integration/request-catalog.mjs` 在隔离 GitHub CI 中验证越权、无任命、缺失/无效审批链、无效审批人、敏感内容拒绝、并发前置版本、幂等重放、版本留存、下线及 REQ 不能提交；迁移账本与 readiness 同步到 006。
- 由服务所有者、OA 管理员确认试点 REQ 清单、审批矩阵、模板、动态主管和系统负责人来源、有效期及代理审批规则。确认后 P1-06 接入真实钉钉 OA 创建/回调/对账，再由 P1-07 实现审批后的受控人工交付与回收。未经这些验收不得将 `available` 置为 true。
- 完整的监控与配置项关联仍为二期 P2-02/P2-03，完整安全事件为三期 P3-01；一期安全入口保护仍须验收。
